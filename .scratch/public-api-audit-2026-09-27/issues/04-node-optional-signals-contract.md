## Уже закрыто тикетом 03

- Ресайз узла без сигналов размера хранится в модели по осям: `resizedWidth`/`resizedHeight` (`models/node.model.ts:102-110`).
- `nodesChanges.size` сообщает `mode: { width, height }`; docs велят сохранять только оси `explicit` (`apps/docs/src/app/categories/nodes/resizer/index.md:48-54`).
- JSDoc `NodeSizeChange` исправлен (`types/node-change.type.ts:17`).
- Отрисованный размер приложение читает через `VflowComponent.getNodeRect(id)`.

## Проблема

1. **Сигнал размера, дописанный в объект узла позже, модель не видит.** По чтению кода, проба после 03 не запускалась.
   - `explicitWidth` читает `rawNode.width?.()` внутри `computed` (`models/node.model.ts:109-110`). Появление свойства на объекте не реактивно, и `computed` остаётся подписан только на `resizedWidth`.
   - Модель переиспользуется по ссылке на объект узла (`utils/identity-checker/reference-identity-checker.ts:15`), так что новый массив с тем же объектом её не пересоздаёт.
   - `setExplicitSize` выбирает цель в момент вызова: `rawNode.width ?? resizedWidth` (`models/node.model.ts:294-297`). После `node.width = signal(300)` следующий ресайз пишет в сигнал приложения, который модель не читает: inline-размер не меняется.
   - Рабочий путь один — замена объекта узла: новая модель, пересоздание view, `remove`+`add` в изменениях.
   - Docs говорят «persist an axis», но не говорят, куда и как вернуть размер в `Node`.
2. **Опциональные сигналы — три разных вида, а выглядят одинаково.**
   - Пишет библиотека: `selected` (выделение), `width`/`height` (только ресайзер), обязательный `point`. Без сигнала значение живёт в модели: `getNode(id).selected` равен `undefined`, конструктор берёт сигнал приложения, только если он есть (`models/node.model.ts:220-236`; рёбра — `models/edge.model.ts:167-186`).
   - Библиотека только читает: `draggable`, `extent`, `data`, `selectable`, `focusable`, `ariaLabel`, `ariaDescription`, `domAttributes`. Отсутствие означает дефолт или настройку flow. `parentId` пишет только утилита `reparentNodes`, которую вызывает приложение (`utils/graph-operations.ts:175-176`).
   - `width`/`height` ещё и переключают режим оси: наличие сигнала делает её `explicit`.
3. **`useDefaults` влияет не на поведение.** Фабрики `createNode(s)`/`createEdge(s)` имеют по три overload'а с этим флагом (`interfaces/node.interface.ts:76-121`, `interfaces/edge.interface.ts:58-122`). Дефолты модель подставит сама; флаг решает только, какие сигналы получит приложение и будут ли они обязательными в типе (`NodeWithDefaults`, `EdgeWithDefaults`). `{ useDefaults: false }` используют только spec-файлы библиотеки; в docs — ни одного вызова.

## Вопросы

- **Как приложение получает explicit-размер после resize:**
  - a) при первом explicit-изменении библиотека дописывает в объект узла `width`/`height`. Так `reparentNodes` дописывает `parentId`, но это утилита, которую вызывает приложение, а не жест;
  - b) модель подхватывает сигналы, появившиеся на объекте, при следующей передаче массива — как `parent` через `nodeByIdMap` (`models/node.model.ts:198-204`). Приложение само дописывает сигнал в обработчике `nodesChanges.size`;
  - c) оставить замену объекта и описать это в docs. Тогда поздно дописанный сигнал надо хотя бы не ломать (пункт 1).
- **`selected` без сигнала.** Создаёт ли модель `selected` на объекте приложения (узлы и рёбра), чтобы выделение всегда было наблюдаемым? Или правило одно: без сигнала значение держит flow, приложение узнаёт о нём из `nodesChanges`/`edgesChanges`? Глоссарий допускает запись в сигналы приложения, но не создание новых: «ngx-vflow may update the application's writable signals».
- **Нужен ли `useDefaults`** после ответа на предыдущий вопрос? Можно ли свести фабрики к `createNode`/`createEdge` + `map`?

## Исследование (2026-10-03)

Как другие библиотеки отдают приложению размер после ресайза. Проверено по исходникам и документации.

- **React Flow 12.** Ресайзер только описывает изменение: `{ type: 'dimensions', setAttributes, resizing, dimensions }` уходит в `onNodesChange` (`NodeResizeControl.tsx`). `width`/`height` в узел пишет приложение через `applyNodeChanges`: копия узла `{ ...element }`, затем `element.width = change.dimensions.width` (`packages/react/src/utils/changes.ts`). Узлы без изменений остаются теми же объектами; view привязан к `id` и не пересоздаётся.
- **Vue Flow.** Та же схема: ресайзер шлёт `dimensions` с `updateStyle: true` через `nodesChange`, `applyChanges` пишет `style.width`/`height` в существующий элемент.
- **Foblex Flow.** `fNodeSize` — обычный input, `fNodeSizeChange` — output в конце ресайза. В своё состояние пишет приложение.
- **Svelte Flow.** Ресайзер сам пишет в привязанный массив: `store.nodes = store.nodes.map(...)` с `{ ...node, width, height }` (`ResizeControl.svelte`). Это двусторонняя привязка `bind:nodes`, на которую приложение согласилось.
- **ng-diagram.** Библиотека пишет `size` в свою модель («The node's size is updated in its data model»); модель — хранилище библиотеки, а не объекты приложения.

Вывод: замены объекта с пересозданием view (вариант c) не требует никто. Там, где состоянием владеет приложение (React Flow, Vue Flow, Foblex), размер возвращает в данные само приложение по событию — это вариант b. Сама библиотека пишет только там, где у неё своё хранилище или двусторонняя привязка массива.

## Answer

Решения пользователя, 2026-10-03.

1. **Размер после ресайза — вариант b.** Библиотека не дописывает `width`/`height` в объект узла. Приложение, которому нужен размер в данных, дописывает сигнал в обработчике `nodesChanges.size` (оси с `mode: 'explicit'`) и передаёт новый массив; модель перечитывает сигналы размера объекта при смене массива, сигнал приложения побеждает внутреннее значение ресайзера. Замена объекта узла для этого не нужна.
2. **`selected` без сигнала остаётся в модели.** Правило одно для всего, что пишет библиотека (`selected`, `width`/`height`): есть сигнал приложения — библиотека пишет в него; нет — значение держит flow и сообщает о нём через `nodesChanges`/`edgesChanges`. Сигналы на объектах приложения библиотека не создаёт. Три вида опциональных сигналов (пишет библиотека / только читает / переключает режим оси) описать в docs.
3. **`useDefaults` убрать.** `createNode(s)`/`createEdge(s)` всегда создают сигналы с дефолтами, как сейчас по умолчанию. Множественные формы остаются. Минимальный объект приложение пишет литералом с `signal()`.

ADR не нужен: решения не расходятся с ADR-0002 (библиотека обновляет только сигналы, которые дало приложение). В `CONTEXT.md` уточнён термин Application-owned state.

Реализация — тикет 21.
