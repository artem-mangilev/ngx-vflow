# React Flow keyboard editing and announcements

Subsequent decision, 2026-09-05: the user requested rolling back issue 11; keyboard connection creation is unsupported for now. These findings are retained as research, not an implementation commitment. See [issue 11](issues/11-implement-keyboard-editing-and-announcements.md).

Checked 2026-09-05 for issue 11, particularly Q5 (handle focus eligibility) and Q7 (announcement timing). Inspected the React package and shared system code at upstream HEAD `0a1f9575b25679f2880175de8d3eae21aedde921`, resolved with `git ls-remote` and checked out locally. Its package declares version `12.11.6`; this is a source snapshot, not a verification of the latest published npm release. [Package](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/package.json#L1-L3)

No browser or screen-reader tests were performed. Findings below describe built-in source behavior, not what application-provided custom nodes can implement or what a particular screen reader will speak.

## Verified facts: handle navigation and connections

- **React Flow has no built-in handle Tab/keyboard connection workflow in this snapshot.** `Handle` renders a `div` with mouse, touch, and optional click handlers, but no built-in `tabIndex`, keyboard handler, role, or ARIA label. It accepts additional div attributes through `...rest`, so an application can supply those itself. [Handle type](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L36-L40), [rendered handle](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L239-L278)
- `isConnectableStart` and `isConnectableEnd` independently describe starting and accepting connections, and both default to true. These are connection eligibility flags, not built-in focus eligibility flags. `isConnectable` also participates in connection styling/validation. [Handle defaults and indicators](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L88-L102), [indicator conditions](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L252-L268), [endpoint validation](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/XYHandle.ts#L287-L315)
- Node `focusable` controls the wrapper's `tabIndex` and keyboard/focus handlers. It is resolved separately from `connectable`, and the child node component is still rendered; there is no descendant-wide inert/disabled setting here. Built-in handles consequently have no Tab eligibility rule to inherit from the wrapper. [Capability resolution](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/NodeWrapper/index.tsx#L64-L67), [wrapper and child](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/NodeWrapper/index.tsx#L219-L247)
- `connectOnClick` supplies a click/tap start-and-complete path, not an Enter/Space keyboard implementation. It remembers the first handle and validates the second through `XYHandle.isValid`. This is useful evidence for shared connection validation, but it does not establish keyboard cancellation, invalid-target recovery, or focus-exit behavior. [Click connection handler](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L185-L237)
- The shared default config contains `handle.ariaLabel`, but React's `Handle` does not consume it. A documented/configured message key is not evidence that the React handle renders that accessibility behavior. [Config key](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/constants.ts#L59-L64), [React handle](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L88-L278)

## Verified facts: live messages

- React's live region reads a single `ariaLiveMessage` string and renders `aria-live="assertive"` plus `aria-atomic="true"`; it is not mounted when keyboard accessibility is disabled. There is no queue, timeout, debounce, blank-and-reinsert mechanism, or action-priority scheduling in this component. [Live region](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/A11yDescriptions/index.tsx#L23-L49)
- A repository search of `packages/react/src` for `ariaLiveMessage` finds one built-in interaction writer: the node wrapper's selected-node arrow-key handler. It writes immediately for each handled keydown, including autorepeat; there is no `event.repeat` filter or 200 ms coalescing. The other occurrences are initial state, type declarations, and the live-region reader. [Writer](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/NodeWrapper/index.tsx#L128-L161), [initial string](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/store/initialState.ts#L137-L140)
- The message uses the focused wrapper node's existing absolute coordinates, truncated via `~~`, **before** calling `moveSelectedNodes`. Movement then computes constrained/snapped positions for all selected draggable nodes. The default message is singular; there is no moved-group count or post-movement summary. Inference: copying this writer would also copy potentially stale coordinates and messages even when constraints prevent movement. [Writer ordering](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/NodeWrapper/index.tsx#L142-L159), [movement](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useMoveSelectedNodes.ts#L19-L64), [message formatter](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/constants.ts#L47-L48)
- The built-in selection, connection, and deletion paths do not write live messages. Therefore React Flow supplies no precedent for a selection summary, immediate connection/deletion messages, or canceling pending movement text in favor of those actions. [Node selection](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/NodeWrapper/index.tsx#L128-L142), [edge selection](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/EdgeWrapper/index.tsx#L169-L181), [connection](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L124-L138), [deletion](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useReactFlow.ts#L163-L200)
- Identical text is not explicitly forced to generate a new DOM mutation; the live region simply selects the store string. This is not an announcement deduplication policy or a guarantee about actual speech. Screen-reader scheduling/repetition requires runtime verification. [Reader](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/A11yDescriptions/index.tsx#L23-L33), [store subscription](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useStore.ts#L34-L44)

## Verified facts: related shortcuts

- The default deletion key is **Backspace only**. Passing `['Delete', 'Backspace']` enables either key. The key hook also parses `+`-separated chords and supports both `event.key` and `event.code`; this differs from ngx-vflow's accepted existing physical-key alternatives contract. [ReactFlow default](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/container/ReactFlow/index.tsx#L65-L72), [key parser](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useKeyPress.ts#L72-L97), [key/code matching](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useKeyPress.ts#L170-L189)
- Deletion listens on `document` by default; it is not limited to a focused node/edge wrapper. The global hook invokes `deleteElements` with selected nodes/edges when the pressed boolean becomes true, even for an empty selection. Repeated keydowns keep that boolean true, so ordinary autorepeat does not retrigger its effect; there is no explicit repeat-event guard. [Global deletion effect](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useGlobalKeyHandler.ts#L24-L37), [document target and pressed state](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useKeyPress.ts#L99-L134)
- Deletion suppresses inputs even with modifiers. The shared exclusion recognizes input/select/textarea, a direct target with a `contenteditable` attribute, and targets inside `.nokey`; it uses the composed path for shadow DOM. Buttons and links are treated specially for `preventDefault`, but are not blanket-excluded from shortcut activation. [Deletion options](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useGlobalKeyHandler.ts#L28-L29), [excluded targets](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/utils/dom.ts#L38-L48), [button/link handling](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/hooks/useKeyPress.ts#L104-L125)
- Built-in selection keys are fixed Enter, Space, and Escape; movement uses arrow keys with a fixed Shift multiplier of four. Node key handling checks the shared input exclusion but does not require `event.target === event.currentTarget`; edge selection lacks that input exclusion. These details should not replace ngx-vflow's already-agreed embedded-control isolation. [Selection keys](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/constants.ts#L40), [node handler](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/NodeWrapper/index.tsx#L128-L161), [edge handler](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/EdgeWrapper/index.tsx#L169-L181)

Official documentation corroborates the public boundary: accessibility describes Tab navigation of nodes/edges; Handle exposes connection flags and div props; ReactFlow documents Backspace and configurable alternatives. [Accessibility guide](https://reactflow.dev/learn/advanced-use/accessibility), [Handle API](https://reactflow.dev/api-reference/components/handle), [ReactFlow keyboard props](https://reactflow.dev/api-reference/react-flow#keyboard-props), [useKeyPress API](https://reactflow.dev/api-reference/hooks/use-key-press)

## Recommendations for ngx-vflow (not React Flow behavior)

These are the original research recommendations. Subsequent grilling accepted Q5, rejected Q7's timed coalescing, and settled invalid-target recovery and focus-exit cancellation. The current decisions are recorded in [issue 11](issues/11-implement-keyboard-editing-and-announcements.md).

- **Q5:** Keep the proposed stable native Tab order: include a handle if resolved capability policy permits starting **or** accepting a connection. An accept-only handle must remain reachable to complete Q4's keyboard workflow. Exclude fully unavailable handles from Tab, retaining their accessible descriptions. A nonfocusable node wrapper should not remove its handles or application controls from navigation. React Flow cannot settle this question because it has no built-in equivalent.
- **Q7:** Keep the proposed 200 ms quiet-period movement summary as an ngx-vflow policy, subject to screen-reader verification. Use actual resulting positions/counts and omit no-op movement. One selection message per command and immediate connection/deletion-request messages can supersede stale pending movement messages. React Flow supports none of those scheduling details; its assertive region alone is not a reason to copy its interruption behavior.
- Keep accepted Q4 and Q6. Enter/Space connections and Escape cancellation extend beyond React Flow's built-in keyboard behavior. Delete plus Backspace, wrapper-local scope, empty/repeat suppression, and application-owned structural requests are intentional ngx-vflow choices; copying React Flow's global delete listener or chord parser would change the agreed contract.
- Still decide invalid connection recovery and cancellation when focus leaves the flow. React Flow provides no built-in keyboard contract to copy for either case.

## Q10 follow-up: connection preview (same pinned snapshot)

- **Pointer drag:** once the drag-start threshold is crossed (or immediately when it is zero), `connection.inProgress` becomes true. The built-in line renders while that state is active, the flow has width, and `nodesConnectable` is enabled. Its source is the initiating handle center. [Drag start](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/XYHandle.ts#L99-L139), [render gate](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/ConnectionLine/index.tsx#L24-L42)
- **No candidate / invalid candidate:** the line endpoint follows the pointer. **Valid candidate:** the endpoint snaps to that handle's center and adopts its handle position for routing. An invalid candidate can still populate `toHandle`/`toNode`, but does not attract the built-in endpoint. [Endpoint assignment](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/XYHandle.ts#L174-L197), [candidate metadata despite validation failure](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/XYHandle.ts#L305-L317), [built-in path endpoint](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/ConnectionLine/index.tsx#L102-L131)
- **Magnet radius:** the pointer is converted to flow coordinates, then the nearest handle center within `connectionRadius` is considered; the default is 20. The initiating handle is skipped. The search chooses the nearest handle before validity checks, rather than searching for the nearest valid handle; equal-distance candidates prefer the opposite type. A handle directly under the pointer takes priority over the nearest-center candidate during validation. [Pointer conversion](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/XYHandle.ts#L147-L154), [nearest-handle search](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/utils.ts#L28-L75), [pointer hit priority](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/XYHandle.ts#L267-L278), [default radius](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/store/initialState.ts#L146)
- **`connectOnClick` waiting between clicks has no built-in preview line.** The first click stores only `connectionClickStartHandle`; it does not set `connection.inProgress`. Pointer-up clears the separate drag connection. The source handle receives the `clickconnecting` class, but that state alone cannot satisfy the line's render gate. [First click](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L198-L205), [handle class](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/Handle/index.tsx#L252-L260), [pointer cleanup](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/system/src/xyhandle/XYHandle.ts#L230-L235), [connection reset](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/store/index.ts#L442-L449), [render gate](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/ConnectionLine/index.tsx#L24-L42)
- **Custom line exception:** `connectionLineComponent` replaces the path renderer and receives coordinates, candidate metadata, validity status, and pointer position, so it can choose different geometry or suppress drawing. It remains behind the same `inProgress` gate; supplying it alone does not create a preview between clicks. [Custom component invocation](https://github.com/xyflow/xyflow/blob/0a1f9575b25679f2880175de8d3eae21aedde921/packages/react/src/components/ConnectionLine/index.tsx#L45-L97)
- **Implication for ngx-vflow:** React Flow offers a pointer-driven precedent (snap only on a valid candidate), but no keyboard-focused endpoint policy. Whether a keyboard preview connects to any focused handle, only a valid one, or disappears on ordinary nodes/controls remains an ngx-vflow decision; the absence of a pointer means the invalid/no-candidate pointer fallback cannot simply be copied.
