# Дизайн-система @vflow/ui: единый дизайн-код и поставка через генераторы

Статус: направление согласовано 2026-10-17, шкалы токенов — предложение до просмотра превью.
Основание: аудит текущего `libs/ui` (ниже), [план MVP→production](../flow-design-system/plan.md), ADR-0005, ADR-0006, ADR-0008.

## Цель

1. Единый дизайн-код: каждое значение в частях выводится из общей шкалы (цвет, типографика, отступы, размеры, радиусы, elevation, motion). Произвольных значений в частях нет.
2. Универсальный нейтральный визуальный язык в духе Apple (macOS): спокойная нейтральная палитра, один accent, плотная типографика, hairline-разделители, концентрические скругления.
3. Поставка исходников в репозиторий потребителя генераторами (модель shadcn/ui, в Angular — spartan-ng): потребитель владеет кодом и правит его напрямую.

## Решения от 2026-10-17

- **BPMN удалён** (решение пользователя после ревью): entry point `@vflow/ui/bpmn`, страница docs, e2e и стили глифов. Специализированные наборы нотаций в каталог не входят.

- **Модель поставки.** На npm публикуется `@vflow/cli`: генераторы и шаблоны частей и токенов; приложение ничего из него не импортирует (2026-10-18). Части копируются в репозиторий потребителя одной библиотекой и импортируются через alias `@vflow/ui`. Поведение (handle, selection, viewport API) остаётся в core ngx-vflow — это аналог spartan `brain`; копируемые части — аналог `helm`. В скопированном коде нет логики, которую пришлось бы мержить при обновлении.
- **Стилизация — Tailwind utilities** в копируемом коде. Потребителю нужен Tailwind v4. Это отменяет двойную поставку `styles.css` / `styles.source.css` из решения 2026-09-12 и вариант «UI без Tailwind».
- **Генераторы — Nx + Angular CLI.** Одна реализация на `@nx/devkit`; Angular schematics получаются через `convertNxGenerator`. Работают `nx g @vflow/cli:ui node` и `ng g @vflow/cli:ui node`.
- **Значения токенов копируются** генератором `ui` файлом `vflow-ui.css` рядом с глобальным stylesheet (значения, `@theme inline`, маппинг на core) и импортом после `@import 'tailwindcss'`; всё — код потребителя, как у shadcn.
- **Плотность — macOS**: body 13px, caption 11px, контролы 24–28px.
- **CLI повторяет spartan-ng (2026-10-18).** `@vflow/cli` подтверждён пользователем; импорта из пакета нет (2026-10-18), CLI нужен только на время генерации; пакет общий для vflow (в будущем — генератор скиллов). Генераторы, конфиг, раскладка частей и синхронизация шаблонов скопированы с `@spartan-ng/cli` 1.8; отличия перечислены в разделе «Генераторы».
- **Набор ставится целиком (2026-10-18).** Части — одна система в 11 файлах (~425 строк) без npm-зависимостей, поэтому выбора частей, таблицы зависимостей и entrypoint на часть нет. Конфиг — `vflow.json` с разделом `ui`: файл общий для будущих возможностей CLI (скиллы).
- **Выделение — вход части (2026-10-18).** `vuiNode`, `vuiGroup`, `vuiEdge` принимают `selected`; потребитель передаёт `ctx.selected()` (и, если хочет, `ctx.preselected()`) или своё состояние. Части не читают `NODE_REF`/`EDGE_REF`. Директивы `VuiSelected` и `VuiTheme` удалены: тема — атрибут `data-vui-theme` на любом элементе, включая `<html>` в `index.html`.

## Визуальный язык

### Принципы

- Нейтральные серые без оттенка; цвет несёт смысл (accent, selection, тоны), а не декор.
- Ноды плоские: hairline-рамка и тень без размытия. Размытые тени и `backdrop-filter` на нодах запрещены — они растрируются заново на каждом шаге pan/zoom (см. комментарий в `node.directive.ts` и [pan/zoom smoothness](../pan-zoom-smoothness-2026-09-26)). «Материал» (полупрозрачный фон + blur) только у плавающих слоёв: controls, toolbar.
- Концентричность: радиус контейнера = радиус вложенного элемента + отступ между ними.
- Все общие размеры и цвета — из шкал ниже. Деталь одной части (ширина кольца и halo порта, strut слота иконки) — arbitrary value в самой части, а не ключ темы (2026-10-19, правило ослаблено: раньше такие детали становились ключами `@theme` только ради запрета arbitrary values). Системные цвета forced colors и SVG-свойства без utilities — тоже arbitrary, с комментарием.
- Состояния не только цветом: текст/иконка/форма линии остаются (ADR-0006, forced-colors).

### Типографика (2026-10-19: от приложения, как в React Flow UI)

Собственной текстовой шкалы нет: `--vui-font-size`, `text-vui-caption/body` и `font-vui-*` удалены 2026-10-19. Части наследуют шрифт, размер, высоту строки и letter-spacing приложения и берут Tailwind type utilities из его темы: `text-xs` — meta, статусы, edge label, кнопка `sm`; `text-sm` — кнопка; `font-medium` — кнопки и статусы; `font-semibold` — заголовки нод и групп; `font-normal` — meta внутри заголовка. Workspace импортирует `tailwindcss/theme.css` вместо темы приложения. Таблица ниже — исходная шкала 2026-10-17, оставлена для истории.

| Роль       | Размер / высота строки | Начертание | Где                                       |
| ---------- | ---------------------- | ---------- | ----------------------------------------- |
| `caption`  | 11 / 14px              | regular    | meta, статусы, edge label, external label |
| `body`     | 13 / 18px              | regular    | содержимое, поля, кнопки (semibold)       |
| `headline` | 13 / 18px              | semibold   | заголовки нод и контейнеров               |

Семейство шрифта не задаётся: части наследуют шрифт приложения (`--vui-font-sans` со стеком `system-ui` удалён 2026-10-18). `font-mono` удалён 2026-10-17: ни одна часть и ни одно демо его не использовали. Все размеры в px — граф масштабируется zoom, а не root font-size.

Правила текста (2026-10-17): части наследуют семейство шрифта приложения (2026-10-18: шрифт диктует потребитель, `--vui-font-sans` удалён) и его `letter-spacing` (2026-10-19: сброс удалён) и сами задают размер, высоту строки и насыщенность; область темы включает `antialiased`. Элементы заголовка выравниваются по базовой линии первой строки title (слот иконки получает нулевую опорную строку). Слот `vuiIcon` универсальный (2026-10-17): минимум 16px в ширину и строка в высоту, растёт по содержимому; опорная строка центрирована в слоте, поэтому центр слота совпадает с центром первой строки title при любом размере (иконка 12–40px, аватар, инициалы). Ставится на обёртку: на `svg`/`img` псевдоэлемент не рисуется. Роль `title` 15/20 удалена: заголовок контейнера — headline. Типографика контента внутри нод остаётся за потребителем; шрифт docs — системный, как у частей.

### Отступы и размеры

- Сетка 4pt: именованные ключи `--spacing-vui-N = N × --vui-space` (N = 0–8; 10–16 удалены 2026-10-17 — их не использовала ни одна часть), utilities `p-vui-3`, `size-vui-7`. Глобальный `--spacing` потребителя не переопределяется.
- Высота контролов: `sm` 24px (иконки в toolbar), `md` 28px (кнопки, controls), `lg` 32px.
- Строка (`vuiRow`): 32px; внутренние отступы ноды 12px; gap 8px.
- Порт: 16px (4 шага) с рамкой 2px цвета `surface`, видимая точка 12px. Порт — сама зона захвата (увеличенной hit area у core нет), поэтому меньше прежних 14px не делаем.

| Материал              | `surface` 80% + `backdrop-blur 20px saturate 180%`            | то же                                                             | Только уровень 1   |

### Выделение, фокус, motion

- Выделение ноды/контейнера: `outline 2px selection`, offset 2px, радиус `radius-surface`; ребро — `stroke selection`.
- Focus-visible контролов: то же кольцо. Core-фокус получает `--v-focus: selection`, `--v-focus-radius: radius-surface`.
- Длительность и кривая переходов — Tailwind defaults приложения (`--default-transition-duration`, `--default-transition-timing-function`); `--vui-duration` и `--vui-ease` удалены 2026-10-19 (второй был ключевым словом `ease`). Workspace задаёт те же defaults в `libs/ui/src/styles.css`. При `prefers-reduced-motion` пульс статуса выключен.
- Forced colors сохраняют текущие правила (`Highlight`, `ButtonText`, `CanvasText`).

### Два параметра вместо каталога значений (реализовано в 01–02; `--vui-font-size` удалён 2026-10-19)

Все шкалы выводятся в `@theme inline` из `--vui-font-size` (13px), `--vui-space` (4px) и `--vui-radius` (6px): caption/title = body ∓ 2px, высоты строк = размер + 1/5/7px, `radius-surface` = `--vui-radius + --vui-space` (концентричность сохраняется при любом переопределении). `inline` вставляет выражение в utility, поэтому переопределение на любом элементе пересчитывает части внутри него.

Дефолтная тема Tailwind в workspace импортируется (2026-10-19) только как замена темы приложения для type utilities и transition defaults; `p-3`, `rounded-lg` и прочие шкалы Tailwind в частях не используются. Это проверяется на ревью, без скрипта (`check-styles` удалён 2026-10-19): каждый класс части — utility из шкал `vui`, arbitrary values только из белого списка (системные цвета, SVG-свойства без utilities, локальные переменные частей из токенов темы).

## Tailwind в проекте потребителя

- `vflow-ui.css` регистрирует токены через `@theme inline` в собственном пространстве `vui`: `--color-vui-surface`, `--radius-vui-surface`, `--spacing-vui-3` и т.д. Utilities — `bg-vui-surface`, `rounded-vui-surface`, `p-vui-3`. Это исключает коллизии с темой приложения (`bg-surface`, `bg-background` у shadcn-подобных тем) и не требует глобального Tailwind `prefix()`, который настраивает потребитель.
- Значения тем (решение 2026-10-19, ADR-0005, вариант Б аудита `tokens-audit-2026-10-19.md`): цвета, которые есть в core (`canvas`, `surface`, `foreground`, `muted`, `border`, `selection`), тема задаёт прямо core-токенами `--v-*`, и части читают их же; `--vui-*` — только то, чего в core нет (`surface-muted`, accent, тона, тени, шкалы). Одно имя на понятие, переопределение на любом поддереве перекрашивает и flow, и части. Шкалы — в `:root`, светлая тема (и `--v-*`, и `--vui-*`) — в `:root` и `[data-vui-theme='light']`, тёмная — в `[data-vui-theme='dark']` (см. ниже). `@theme inline` ссылается на значения, поэтому смена темы — только смена переменных.
- Шрифт, letter-spacing и тайминг переходов — от приложения: сброс `letter-spacing` (`tracking-vui-normal`) удалён 2026-10-19.
- Светлая тема — по умолчанию на `:root` (решение 2026-10-19, как `:root`/`.dark` у shadcn): скопировать файл генератором — это и есть opt-in, поэтому все flow приложения получают тему без атрибута. `[data-vui-theme='light']` форсирует светлую внутри тёмной области, `[data-vui-theme='dark']` переключает любое поддерево. `color-scheme` и `accent-color` ставит только явная область, чтобы не трогать собственную тему приложения. ADR-0005 уточнён; атрибуты в docs-демо откатили, core-only редактор из демо тем убран.
- Цвета — oklch (решение 2026-10-19): одна запись для всех значений, включая прозрачные и тени; производные шаги смешиваются в oklab. Значения — конвертация прежних hex с округлением до 3 знаков (отклонение ≤ 2/255 на канал).
- `vuiStatusBusy` и `vui-pulse` удалены 2026-10-19: статус — только тон; для «идёт работа» потребитель кладёт свой спиннер внутрь `vuiStatus`.
- Скопированные части лежат в репозитории потребителя (`componentsPath`), Tailwind находит их автоматическим source detection; `@source` для `node_modules` не нужен.
- Tailwind `prefix()` потребителя не поддерживается, как и у spartan: пространство `vui` уже исключает коллизии.
- Длинные строки классов в `host.class` группируются по назначению (layout / цвет / состояния / forced-colors), чтобы файл было легко править.

## Генераторы

Поведение скопировано с `@spartan-ng/cli` 1.8 (`init`, `ui`, `ui-theme`, `components.json`), но генератор один — `ui` (решение 2026-10-19): `init` и `ui-theme` spartan стали его шагами. Поддерживаются Angular 20, 21 и 22 (peers `ngx-vflow`; проверено 2026-10-18 смоуком на свежих Angular CLI 20–22 и Nx 21–22, сам смоук из репозитория удалён — интеграцию проверяют на отдельных репозиториях). Потребитель ставит `npm i -D @vflow/cli` (зависимости — `nx`, `@nx/devkit`, `enquirer`; `@nx/angular` — optional peer, нужен только в Nx); Tailwind v4 — предусловие: CLI его не ставит, но проверяет (отличие от spartan, 2026-10-18: на Tailwind 3 пресет ломает сборку, без Tailwind части молча остаются без стилей). `ng-add` нет.

### Шаги

Генератор — список шагов из `libs/cli/src/steps`. Каждый шаг проверяет, добавляет недостающее, ничего не перезаписывает и бросает ошибку до записей (брошенный генератор не пишет ничего). Поэтому один `ui` и настраивает workspace, и подключает токены к другому приложению (`--project`), и после обновления CLI добавляет новые части. Будущие генераторы (`bpmn`, скиллы) собираются из тех же шагов плюс своих.

| Шаг              | Что делает                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ensureNgxVflow` | `ngx-vflow` в версии CLI, если его нет (аналог `@spartan-ng/brain`), `@angular/cdk` в мажоре Angular; старший мажор `ngx-vflow` ниже CLI — ошибка |
| `ensureUiTokens` | Токены в приложении (ниже); workspace без приложений пропускается с подсказкой                                                                    |
| `ensureUiParts`  | Конфиг, копирование всего набора одной библиотекой или tsconfig path                                                                              |

### Токены (`ensureUiTokens`)

Публичного `ui-theme` нет (решение 2026-10-18): тема одна, выбирать нечего. Приложение — из `--project`, вопроса или единственного в workspace; stylesheet — из `--stylesEntryPoint` или поиска. Tailwind проверяется по установленному `node_modules/tailwindcss`, без него — по диапазону в `package.json` (подходит любой, допускающий 4).

- Stylesheet ищется как у spartan: `styles.css|scss|sass|less` в `sourceRoot` проекта, затем файлы проекта из `build.options.styles`; CSS-файл выигрывает у более раннего Sass/Less; не нашёлся — ошибка с подсказкой про `--stylesEntryPoint`. Не `.css` (Sass, Less) — ошибка: Tailwind 4 компилирует только CSS, а вставка с `;` и `{}` ломает синтаксис Sass с отступами.
- `vflow-ui.css` копируется рядом со stylesheet, `@import './vflow-ui.css';` вставляется сразу после ведущих `@charset` / `@import` / `@layer …;`, чтобы `@import 'tailwindcss'` шёл первым и CSS оставался валидным.
- Повторный запуск ничего не дублирует: существующий `vflow-ui.css` и импорт сохраняются — генератор пишет об этом; значения правят на месте.
- Ведущие комментарии (`/* You can add global styles… */` из `ng new`) пропускаются, поэтому импорт встаёт после `@import 'tailwindcss'`, а не над ним.
- Отличия от spartan: темы одна пара light/dark, поэтому нет выбора темы и опции `--theme`; нет `--prefix` (тема уже ограничена `[data-vui-theme]`); не переписываются Tailwind-импорты и не добавляется `@layer base` для `body` — части не зависят от слоёв и не стилизуют страницу.

### Части (`ensureUiParts`)

- **Конфиг `vflow.json`** — аналог `components.json`, общий для возможностей CLI; UI читает и валидирует только раздел `ui`, ошибки печатаются таблицей. Раздел создаёт первый запуск по вопросам: `componentsPath` (по умолчанию `libs/vflow-ui` — `libs/ui` слишком частое имя в Nx-монорепо; без вопроса при `--directory`), `importAlias` (по умолчанию `@vflow/ui`; без вопроса при `--importAlias`). Без интерактивного терминала (`--no-interactive`, CI) вопросов нет — берутся значения по умолчанию. `buildable` не спрашивается и не хранится (2026-10-19): `--buildable`, иначе дефолт `@nx/angular:library` из `nx.json`, иначе `true`.

  ```json
  { "ui": { "componentsPath": "libs/vflow-ui", "importAlias": "@vflow/ui" } }
  ```

- **Набор целиком**: аргумента с именем части нет. Файлы ложатся в `<componentsPath>/src/index.ts` и `src/lib/*`; части импортируют друг друга относительно, как в `libs/ui`.
  - Angular CLI: path `<importAlias>` → `./<componentsPath>/src/index.ts` в корневом tsconfig и `<componentsPath>/src/**/*.ts` в `include` `tsconfig.app.json`; файлы правятся через `jsonc-parser` с сохранением комментариев.
  - Nx: одна Angular-библиотека в `componentsPath` с import path `<importAlias>`. Файлы, которые пишет генератор библиотек Nx (`src/lib/*`, `src/index.ts`), заменяются набором; правила ESLint библиотеки не меняются — префикс селекторов `vui` задаётся при создании.
  - Режим Angular CLI включает флаг `angularCli`, который передаёт schematic-обёртка (05), как у spartan.
- **Первый запуск в непустую папку** (`componentsPath` уже содержит файлы, alias ещё нет) — ошибка до любых записей, включая `vflow.json`: генератор не перезаписывает и не удаляет файлы приложения. В Nx после `libraryGenerator` удаляются только файлы, созданные им в этом же запуске (`tree.listChanges()`).
- **Повторный запуск в другую папку** (`--directory` не совпадает с установленным `componentsPath`) — ошибка.
- **Повторный запуск** (alias уже есть в tsconfig paths, как признак установки у spartan; например, после обновления `@vflow/cli`) создаёт недостающие файлы и не трогает существующие; `index.ts` не переписывается — генератор печатает части, которых в нём нет. Перезаписи и `--overwrite` нет.

### Каталог

`node`, `row` (бывший `field`, переименован 2026-10-17), `group` (с `vuiGroupHeader`; бывший `container`, переименован 2026-10-18 — название не говорило, что это группа нод), `text`, `port`, `status`, `edge`, `toolbar`, `button`, `controls`. `external-label` удалён 2026-10-17 (наследие BPMN), `theme` и `selected` — 2026-10-18 (директивы заменены атрибутом темы и входом `selected`). Имена селекторов и классов остаются `vui*` / `Vui*` (ADR-0008); `index.ts` экспортирует директивы и массив `Vui`.

## Источник истины в репозитории

Раскладка как у spartan (`libs/helm` + `libs/cli` + `libs/tools`):

- `libs/ui` — приватная библиотека `@vflow/ui` с одним entrypoint и без сборки; docs и e2e импортируют `@vflow/ui` — тот же путь, что у потребителя после `ui`.
- `libs/cli` — публикуемый `@vflow/cli`: `generators.json` с секциями `generators` и `schematics`, `compat.ts` на генератор, шаги в `src/steps`; релизится одной версией с `ngx-vflow` (тег `release`), так как шаг `ensureNgxVflow` ставит `ngx-vflow` в версии CLI.
- Скрипт `libs/ui/scripts/sync-cli.mjs` (`nx run ui:sync-cli`, аналог `hlm-to-cli-generator`; скрипт, а не Nx-генератор, как остальные скрипты `libs/ui`) копирует `libs/ui/src` в `libs/cli/src/steps/templates/ui` с суффиксом `.template` (`public-api.ts` → `src/index.ts`), `vflow-ui.css` в `libs/cli/src/steps/templates`. Копии дословные: импорты внутри набора относительные. Результат в `.gitignore` (единственный источник — `libs/ui`); `cli:build` и `cli:test` сначала запускают `ui:sync-cli`, поэтому отдельной проверки расхождения нет.
- Токены — один файл `libs/ui/src/vflow-ui.css`, его импортирует `styles.css` библиотеки. Значения тем лежат в `@layer base` (у потребителя ниже utilities, неслоёные стили приложения побеждают).
- Docs: у каждой части — исходник файла; страница конфига `vflow.json`; страница токенов показывает шкалы в обеих темах.

## Не входит

- `healthcheck`, `info` и `migrate-*` генераторы spartan — появятся с первыми breaking changes частей.
- Генератор скиллов для агентов — будущий генератор того же `@vflow/cli` (решение 2026-10-18: пакет общий для vflow, не только для UI; поэтому UI-генератор называется `ui`, а файл токенов — `vflow-ui.css`).
- Дополнительные темы кроме light/dark.
- Новые части каталога и изменения core-поведения.
- Вариант без Tailwind.
