# Ресайзер: источник размера ноды и позиционирование хендлов

Status: research

## Симптом

В демо Introduction → Overview нода «Click to Resize» показывает рамку ресайзера и хендлы не по видимому контенту. То же самое в демо Nodes → Resizer.

## Воспроизведение (docs, 2026-09-13)

Замеры через DOM на странице overview, нода `transform`:

| Элемент                                                                 | Размер, flow units |
| ----------------------------------------------------------------------- | ------------------ |
| `NodeModel.width/height` = inline style `.wrapper` = бокс `.vflow-node` | 100 x 50           |
| `.transform-node` (CSS `min-width: 240px; min-height: 320px`)           | 240 x 320          |

Контролы ресайзера (`.resize-control`) обрисовывают бокс 100x50. Хендл `position="right"` получает `right: 0` относительно `.vflow-node`, то есть стоит на x = 100 внутри контента шириной 240. Output-нода честно показывает `W: 100 H: 50`.

После перетаскивания нижнего правого угла примерно на +125/+190 модель стала 212 x 162, а `.transform-node` остался 240 x 320: визуально нода не изменилась, хендл сдвинулся вместе с невидимым боксом.

В демо Resizer: хост 100 x 50, `.custom-node` 150 x 100.

## Причины

1. **Наличие `[resizable]` переключает ноду в режим явного размера.** `ResizableComponent.ngOnInit` ставит `controlledByResizer = true`, и `node.component.html` сразу пишет `width/height` модели в inline style `.wrapper`. Для html/component нод без `width/height` в данных модель содержит `NODE_DEFAULTS` 100 x 50 (`createNodes` с `useDefaults` подставляет их в сигналы). Фикция 100 x 50 становится реальным боксом.
2. **Измеряется библиотечная обёртка, а не контент.** `nodeResizeController` читает `offsetWidth/Height` у `.wrapper`, а это её же inline размер из модели. Обратной связи от контента нет, цикл замкнут на неверном значении.
3. **Размер применяется к одному элементу, а CSS-ограничения живут на другом.** Ресайзер читает `min-width/min-height` из computed style элемента с `[resizable]` (внутреннего), а inline размер получает `.wrapper`. Браузер клампит внутренний элемент, обёртка об этом не знает, контент переполняет бокс.
4. **Стартовые значения ресайза не из DOM.** `createResizer` берёт `prevValues` из модели (100 x 50), а границы min 240 x 320 из CSS. Алгоритм клампа (унаследован из xyflow `getDimensionsAfterResize`) предполагает, что стартовый размер уже внутри `[min, max]`; при старте ниже минимума кламп уменьшает прирост вместо дотягивания до минимума. Отсюда 212 вместо ≥ 240.

Хендлы не виноваты: `HandleModel.measure` и CSS `right: 0` честно следуют боксу `.vflow-node`. Бокс неверен, а не позиционирование.

## Как это устроено у других

### React Flow (xyflow)

- `NodeResizer` рендерится внутри пользовательского компонента ноды, контролы позиционируются процентами относительно `.react-flow__node` (`left: 100%`, `top: 50%`). Контролы, хендлы и inline размер живут на одном боксе.
- Два поля: `measured` (только чтение, из ResizeObserver, `offsetWidth/Height`) и `width/height` (явный размер). `NodeWrapper` пишет inline `width/height` только если задан `node.width` или `style.width`. Контент-размерная нода inline размера не имеет.
- `XYResizer` на `start` берёт `node.measured`, на `drag` пишет `width/height` и одновременно `measured`, чтобы рёбра обновились в том же кадре.
- `handleBounds` перемеряются ResizeObserver'ом после каждого изменения размера; рёбра берут `positionAbsolute + handleBounds`.
- Известные проблемы: после первого ресайза нода навсегда становится явной по размеру (#4739); `content-box` расходится с процентными контролами (обсуждение #3058).

### ng-diagram (Synergy Codes)

- `<ng-diagram-node-resize-adornment>` оборачивает контент ноды (`position: relative; width/height: 100%`) и рендерит линии и углы внутри себя.
- В модели есть флаг `autoSize` (по умолчанию `true`). `NodeSizeDirective` пишет inline размер только при `autoSize: false`. Измеренный размер (ResizeObserver, `borderBoxSize`) зеркалится в `size`, но не в DOM.
- Жест ресайза шлёт `disableAutoSize: true` вместе с `size`: нода переходит в явный размер в момент первого перетаскивания. Клик без движения режим не меняет.
- Во время жеста измерения ResizeObserver для этой ноды отбрасываются («resize action is the source of truth»), после жеста нода и порты принудительно перемеряются, чтобы CSS-кламп (`min-width`) вернулся в модель.
- Порты позиционируются CSS, их `measuredPorts` перемеряются синхронно при изменении `size` во время ресайза; роутинг рёбер откладывается до обновления `measuredPorts`.

### Foblex Flow

- `fResizeHandle` ставится внутрь элемента с `fNode`; библиотека только вешает классы, стили дают миксины (`position: absolute; right: 0; bottom: 0; translate 50%`).
- Ресайзится сам хост `fNode`: библиотека пишет inline `width/height` и `transform` в него напрямую на каждый `pointermove`, а в конце эмитит `fNodeSizeChange` с полным `IRect`.
- Базовый размер перед жестом меряется из DOM (`offsetWidth/Height`, позиция из `getBoundingClientRect` с делением на scale). Нода без `fNodeSize` после первого ресайза получает явный px-размер.
- Коннекторы измеряются из DOM на каждый `pointermove`, рёбра перерисовываются сразу.
- Минимальный размер по умолчанию — сумма паддингов; в CHANGELOG 18.x зафиксирован баг рассинхрона коннекторов при ресайзе, исправленный per-move обработчиками.

### Общие инварианты у всех троих

1. Ресайзится, измеряется и служит контекстом позиционирования контролов и хендлов **один и тот же элемент**.
2. Модель не навязывает размер контент-размерной ноде, пока пользователь её не потянул. Переключение auto → explicit происходит на первом реальном перемещении, а не при наличии директивы.
3. Стартовые значения жеста берутся из измеренного DOM-размера, поэтому они уже удовлетворяют CSS min/max.
4. После жеста DOM перемеряется и модель сверяется с тем, что реально отрисовано.

## Что нарушено в ngx-vflow

| Инвариант                       | ngx-vflow сейчас                                                                                                                                |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Один бокс                       | Размер пишется в `.wrapper`, контролы позиционируются по `.vflow-node`, CSS min/max читаются с элемента `[resizable]`, контент лежит ещё глубже |
| Auto → explicit на первом жесте | Переключение при `ngOnInit` директивы                                                                                                           |
| Старт из DOM                    | Старт из модели, где для html/component нод лежит дефолт 100 x 50                                                                               |
| Сверка после жеста              | Измеряется `.wrapper`, размер которого равен inline-значению модели; кламп внутреннего элемента невидим                                         |

## Направление

1. **Режим размера в модели.** Ввести явное состояние `auto | explicit` (аналог `autoSize` в ng-diagram, `width/height` vs `measured` в React Flow). Inline размер обёртка получает только в `explicit`. `explicit` включается, если приложение задало `width/height` для html/component ноды, или после первого коммита ресайзера. `controlledByResizer` в текущем смысле («директива присутствует») убрать.
2. **`createNodes` не должен подставлять 100 x 50 в `width/height` html/component нод.** Иначе критерий «приложение задало размер» неотличим от дефолта. Дефолт может остаться как плейсхолдер до первого замера, но не как источник inline стиля.
3. **Один бокс.** Контролы ресайзера рендерить внутри элемента с `[resizable]` (как adornment в ng-diagram и `NodeResizer` в React Flow), а inline размер писать в него же. Тогда CSS `min/max-width`, `box-sizing`, паддинги применяются браузером к тому же элементу, который обрисовывают контролы. `.wrapper` остаётся `max-content` и следует за содержимым, `nodeResizeController` измеряет реальный результат. Альтернатива с сохранением записи в `.wrapper` требует, чтобы `[resizable]` стоял на верхнем элементе с `width/height: 100%` и без собственных min/max, что и сейчас нарушают оба демо.
4. **Старт жеста из измеренного размера.** При `auto` модель уже зеркалит контент (после пункта 1), поэтому `prevValues` в `createResizer` станут корректными без отдельной ветки. Дополнительно защитить `getDimensionsAfterResize` от старта вне `[min, max]`: клампить стартовые значения перед расчётом.
5. **Сверка после жеста.** На `end` принудительно перемерить ноду и хендлы и записать в модель фактический размер (как `invalidateNode` в ng-diagram). Во время жеста ресайзер остаётся источником истины; замеры `.wrapper` в этот момент либо совпадают, либо должны игнорироваться.
6. **Хендлы менять не нужно.** Их геометрия относительно `.vflow-node` корректна; после исправления бокса они встанут на место. Стоит лишь проверить, что `HandleModel.measure` перезапускается после пункта 5 (сейчас `.wrapper` уже наблюдается ResizeObserver'ом).

## Быстрый обход для демо

Задать `width: 240, height: 320` у ноды `transform` в `flow-store.service.ts` и у нод демо Resizer. Это скрывает дефект, а не устраняет.
