# 06. E2E проверка на docs

Status: resolved
Type: task
Blocked by: 05

Playwright в `apps/docs-e2e`:

- Overview: до клика бокс `.resize-control.line` (после выделения) совпадает с `getBoundingClientRect` элемента `.transform-node` с точностью до gap; хендл `handle--right` центрирован на правом краю контента.
- Overview: перетаскивание нижнего правого угла на +80/+80 увеличивает `.transform-node` и значения `W/H` в `Output` на ту же величину с учётом zoom.
- Nodes → Resizer: та же проверка бокса для `.custom-node`; после ресайза меньше `min-width` модель равна `min-width`.
- Stress e2e и `initial-handles.spec.ts` без регрессий.

## Answer

`apps/docs-e2e/resizer.spec.ts`, размеры сравниваются с отрисованными элементами с учётом zoom, без зашитых чисел:

- Overview, до ресайза: рамка контролов совпадает с `.transform-node`, inline ширины нет, правый хендл центрирован на правом краю.
- Overview, жест +80/+60 в экранных пикселях: карточка растёт на `80/zoom` и `60/zoom`, `Output` показывает тот же размер, рамка совпадает, правый хендл на новом краю. Это закрывает непроверенный в тикете 04 пункт о хендлах после жеста.
- Resizer: нода по контенту уже на `min-width`, сжатие ничего не меняет и оставляет её `auto`; рост делает её `explicit`; сжатие за минимум останавливается на `min-width` с правым хендлом на краю.

Исходный сценарий «сжать меньше min-width» оказался неверным: у контент-ноды ширина уже равна минимуму, изменения нет, и по D1 режим не переключается. Тест переписан так, чтобы проверять и это поведение.

Проверки: новая спека 3/3 и 30/30 при `--repeat-each=10`; остальные e2e-спеки 29/29, включая stress; lint `docs-e2e` чистый. `initial-handles.spec.ts` входит в юнит-набор библиотеки, 228/228 после тикета 04.
