# Спецификация: режим размера ноды и единый бокс ресайзера

Status: implemented
Исследование: `report.md` в этой же папке.

## Цель

Ресайзер и хендлы должны всегда описывать тот бокс, который пользователь видит. Для этого библиотека перестаёт навязывать размер контент-размерной ноде, а ресайзер, измерение и контролы работают с одним элементом.

## Термины

- **Размер ноды** (`NodeModel.width/height`): единственное значение, которым пользуются рёбра, хендлы, minimap, fitView, `nodesChanges.size`.
- **Режим размера** (`sizeMode`): `auto` означает, что размер зеркалит измеренный DOM и библиотека не пишет inline width/height; `explicit` означает, что размер задан данными или ресайзером и библиотека пишет его в DOM. Термина в `CONTEXT.md` нет, нужно добавить при реализации.
- **Резайзабельный элемент**: элемент с директивой `[resizable]`. Он получает inline размер; контролы рисуются в слое ноды вокруг него.

## Решения

### D1. `sizeMode` вычисляется, публичного переключателя нет

```
sizeMode = computed(() =>
  rawNode.type === 'template-group' ||
  (rawNode.width !== undefined && rawNode.height !== undefined) ||
  resizedExplicitly()
    ? 'explicit' : 'auto')
```

- Снаружи режим задаётся только наличием `width`/`height` в данных html/component ноды. Это единственная внешняя «настройка».
- Внутри `resizedExplicitly` (внутренний writable signal) ставится ресайзером на первом принятом изменении и не сбрасывается. Клик по контролу без движения режим не меняет.
- Переключение сообщается приложению через `nodesChanges.size`, куда добавляется поле `mode: 'auto' | 'explicit'`. Приложение, которое хочет сохранить пользовательский размер, кладёт его в `width`/`height` данных, и при следующем построении графа режим будет `explicit` уже снаружи.
- Отвергнутая альтернатива: публичный сигнал `autoSize` в `Node` (как в ng-diagram). Он дублирует информацию, которая уже есть в наличии размера, и добавляет состояние, которое приложение должно синхронизировать.

### D2. `createNodes` не подставляет размер html/component нодам

`useDefaults` перестаёт создавать `width: signal(100)`/`height: signal(50)` для `html-template` и component нод. Иначе критерий D1 неотличим от дефолта. `NodeWithDefaults` меняет тип: `width`/`height` для этих типов становятся опциональными. `NODE_DEFAULTS.width/height` остаются начальным значением внутреннего сигнала до первого замера (плейсхолдер, в DOM не попадает).

Для `template-group` ничего не меняется: размер обязателен.

### D3. Один бокс: inline размер на резайзабельном элементе, контролы в слое ноды

- В режиме `explicit` inline `width`/`height` и `box-sizing: border-box` получает элемент с `[resizable]`. Без border-box ширина, записанная ресайзером, и измеренный `offsetWidth` расходятся на паддинги и рамки, и каждый жест наращивал бы ноду.
- `.wrapper` получает inline размер только в `explicit` без резайзабельного элемента (размер задан данными, ресайзера нет). В остальных случаях он `max-content`, и измерение `nodeResizeController` отражает фактический бокс с учётом CSS `min/max` элемента.
- Контролы по-прежнему рендерятся `NodeComponent` в слое ноды через шаблон, который регистрирует `ResizableComponent`. **Отклонение от первоначальной формулировки** «контролы внутри элемента»: карточки нод обычно имеют `overflow: hidden` со скруглением (так сделана transform-нода в Overview), и контролы, выступающие за край на gap и половину размера, обрезались бы. В слое ноды они позиционируются от `.vflow-node`, того же бокса, от которого считаются хендлы, поэтому `position: relative` на пользовательский элемент не навязывается.
- Инвариант одного бокса держится требованием: `[resizable]` стоит на верхнем элементе шаблона без внешних отступов. Тогда `.vflow-node`, `.wrapper` и резайзабельный элемент совпадают.
- `NodeModel.resizable` и `controlledByResizer` удалены. `[resizable]="false"` скрывает контролы внутри шаблона, но элемент остаётся носителем размера. При уничтожении элемента его шаблон снимается с модели, и размер возвращается на `.wrapper`.
- Для `template-group` шаблон группы может продолжать ставить размер из `ctx.width()/height()`; значения совпадают с тем, что ставит `[resizable]`.
- Контролы остаются исключёнными из drag и selection, как сейчас (`NoDragDirective`, `pointer-events`).

### D4. Жест: старт из измеренного, защита клампа, сверка после конца

- Стартовые значения берутся из модели, которая в `auto` уже зеркалит контент. Дополнительно стартовые `width/height` клампятся в `[min, max]` до расчёта `getDimensionsAfterResize`, чтобы старт вне диапазона не уменьшал прирост. Клампится только база расчёта (`startValues`); `prevValues` остаются фактическими, чтобы первое движение гарантированно записало клампнутый размер.
- Первое принятое изменение сначала переводит `resizedExplicitly` в `true`, затем пишет `width/height/point`. Порядок важен: inline размер должен появиться в том же кадре, что и значение.
- Во время `resizing()` `nodeResizeController` не пишет измерения в модель: источник истины у жеста. Когда `resizing()` становится `false`, замер повторяется, и модель получает фактический размер, если CSS его ограничил.
- Геометрия хендлов зависит от размера модели, поэтому `nodeHandlesController` пересчитывает хендлы при его изменении. Сверка меняет размер модели без изменения DOM, и ResizeObserver этого не заметит.

### D5. Хендлы не меняются

Геометрия `HandleModel` относительно `.vflow-node` корректна. После D3 хост `.vflow-node` совпадает с резайзабельным элементом, если тот является верхним элементом шаблона. Документация фиксирует требование: `[resizable]` ставится на верхний элемент шаблона ноды.

## Что ломается

- Тип `NodeWithDefaults`: `width`/`height` опциональны для html/component нод.
- `nodesChanges.size` получает новое поле `mode`.
- `NodeModel.controlledByResizer`, `resizerTemplate`, `resizable` удалены (внутренние, но доступны из тестовых моков).
- Резайзабельный элемент получает `box-sizing: border-box` от библиотеки в режиме `explicit`.

## Проверка

- Юнит: `createNodes` без размеров, `sizeMode` по всем трём источникам, inline размер только после первого принятого изменения, кламп старта, отсутствие записи измерений во время `resizing`, сверка на `end`.
- E2E (docs, страницы Overview и Nodes → Resizer): бокс контролов равен боксу контента до первого ресайза; хендл `right` стоит на правом краю контента; после перетаскивания видимый размер и модель растут одинаково; `Output` показывает размер transform-ноды.
- Регрессии: существующие спеки ресайзера, `initial-handles.spec.ts`, e2e stress.
