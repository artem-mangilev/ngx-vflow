# Аудит @vflow/ui и демо раздела Design system — 2026-11-14

Метод: чтение `libs/ui/src` (тема `vflow-ui.css`, 8 файлов частей, 538 строк) и всех демо в
`apps/docs/src/app/categories/design-system`; живой просмотр шести страниц `localhost:4200/design-system/*` в светлой и
тёмной теме с выделением нод, рёбер и наведением на порты; замеры computed style в Chromium. Сравнение с open-source —

## 2. Использование ДС в демо

### 2.1 Не работает (подтверждено в браузере)

1. **Workflow: состояние рёбер не рисуется.** Правила
   `[data-v-edge]:not([data-v-selected]) .vui-edge[data-state='taken' | 'skipped']`
   (`workflow-demo.component.ts:31-40`) лежат в стилях компонента с эмулированной инкапсуляцией. Angular дописывает
   `_ngcontent` демо к каждому составному селектору, а `[data-v-edge]` — хост из шаблона core с другим атрибутом.
   Замер: у ребра `data-state="taken"` stroke = `--vui-muted`, а не `--vui-success`; после Approve ветка «Needs changes»
   не становится пунктирной. e2e (`design-system.spec.ts:53-72`) проверяет только атрибут, поэтому зелёный.
2. **ERD: действия строк на выделенной таблице не появляются.** `[data-v-selected] .row-action`
   (`entities-demo.component.ts:77-79`) — та же причина; у выделенной таблицы `opacity` кнопок = 0. Сценарий для touch,
   ради которого правило написано, не работает.

3. **`vuiPort`: у уже соединённого порта состояния соединения теряют заливку.** В собранном CSS правило
   `data-[vui-connected=true]:bg-vui-muted` идёт после `data-[v-handle-state=connecting|valid|invalid]:bg-*` при равной
   специфичности (порядок Tailwind детерминирован). Замер: порт в состоянии `connecting` с `data-vui-connected="true"`
   имеет фон `--vui-muted`, а не `--vui-accent`. По тому же порядку правил valid на соединённом порту не станет
   зелёным, а invalid не станет полым — то есть контракт «valid залит, invalid полый, состояние не зависит только от
   цвета» для соединённых портов не выполняется (valid/invalid выведены из порядка правил, вживую не воспроизводил).

Общий вывод по пунктам 1–2: рецепт из Overview «application CSS on the public selectors» ломается в стилях компонента, как только
селектор начинается с хоста core (`[data-v-edge]`, `[data-v-selected]`, `[data-v-node]`). Нужен либо `:host ::ng-deep`
в рецепте, либо способ читать состояние хоста на своём элементе (как части делают через `:is([data-v-selected] *)` в
глобальном Tailwind).

### 2.2 Хром канваса перекрывает содержимое

- Image pipeline: палитра «Add node» закрывает заголовок ноды Number, `vui-controls` закрывает нижнюю строку ноды
  Texture. Условие уточнено при починке: только когда страница загружена в окне до 1024px (ng-doc убирает боковые
  панели, канвас 897–959px, сцена упирается в высоту). В окнах шире канвас не больше 824px, зазор 0–8px — вплотную,
  но без наложения. `fitView` не знает об оверлеях.
- Overview (Themes): `v-minimap` лежит поверх ноды Target и её порта в обоих редакторах.

## 4. Где @vflow/ui уступает

Порядок — по влиянию на «привлекательно и консистентно». В скобках — у кого это есть.

### 4.1 Нет цветовой идентичности

Сцены серо-белые; единственный цвет — синий выделения. У продуктов поверхности тоже нейтральные, но оттенок несёт
смысл: категория на плашке иконки (Dify, n8n, Flowise), тип данных на порту и проводе (Langflow, ComfyUI, Blender),
заметки в 6–7 тонах (n8n, Dify). В ДС для этого нет ничего: `vuiIcon` — пустой слот, палитры нет, поэтому pipeline и
relationships пишут hex руками, а ERD и workflow остаются монохромными. Дешёвый путь показан Vue Flow: одна переменная
на ноду красит рамку, порт и выделение. В `vuiPort` такая переменная уже есть — `--vui-tone`.

Не противоречит решению «один accent»: accent остаётся цветом взаимодействия, палитра — аналог `--chart-1..5` shadcn.

### 4.2 Оболочки знают только одно состояние — selected

| Состояние                           | @vflow/ui                    | У других                                                                          |
| ----------------------------------- | ---------------------------- | --------------------------------------------------------------------------------- |
| hover ноды                          | нет                          | `ring-1` (RF UI), accent border (ng-diagram), шаг тени (Dify, Langflow, Flowise)  |
| selected                            | border + кольцо 1px, жёсткое | мягкое кольцо: 4px 40% (ng-diagram), 6px 10% (n8n), `ring-[3px] ring/50` (shadcn) |
| dragging                            | нет                          | подъём тени (Foblex, Baklava)                                                     |
| drop target                         | нет (демо рисует само)       | inset glow (ng-diagram), `ring-4 ring-primary` (ComfyUI), пунктир (Foblex)        |
| running / success / error / warning | нет                          | рамка-оверлей + иконка: RF UI, n8n (conic-кольцо), Dify, Langflow, ComfyUI        |
| disabled / muted                    | нет                          | grayscale (Langflow), зачёркивание (n8n), оверлей (ComfyUI)                       |

Выделение ноды и акцент порта говорят на разных языках: у порта halo (1px + 4px 28%), у ноды — жёсткие 2px. Мягкое
кольцо в языке порта решило бы и привлекательность, и консистентность.

Статус ноды — не бейдж: решение 2026-10-20 убрать `vuiStatus` (бейдж есть в ДС потребителя) этого не покрывает, рамки
вокруг ноды в spartan или Material нет. Тень: правило «без blur в покое» остаётся; подъём нужен одной перетаскиваемой
или выделенной ноде.

### 4.3 Язык рёбер из одного слова

`vuiEdge` — 2px muted, accent при выделении. Нет hover (Foblex: полупрозрачный широкий штрих; ng-diagram: темнее),
тона, вариантов «пунктир» и «приглушён», анимации выполнения (xyflow `.animated`, RF UI Animated SVG Edge), цвета по
статусу (n8n, Dify-градиент). Линия соединения — не часть; три демо копируют один шаблон. Цвета валидности на самой
линии нет (Baklava), несовместимые порты во время соединения не гаснут (Foblex, Langflow) — замер: при `connecting`
состояние меняется только у исходного порта (тикет handle-eligibility открыт).

### 4.4 Хром канваса неполон и не оформлен

- Фон: токен `--v-background-pattern` есть, но ни одно демо раздела не показывает точки. У n8n, Dify, Langflow
  малоконтрастная сетка точек — базовый признак «редактора».
- Minimap: прямоугольник core без радиуса и тени рядом со скруглённым `vui-controls`; у ng-diagram радиус 1rem и тень.
- Controls: три кнопки без уровня zoom; RF UI — Zoom Slider и Zoom Select с процентами, n8n — reset и tidy.
- Нет части для размещения панелей: демо ставят `position: absolute; z-index: 2` сами, отсюда перекрытия из 2.2.
- Нет Placeholder Node / пустого состояния (RF UI, n8n: пунктирная плитка «+»), «+» на порту и ребре (RF UI Button
  Handle / Button Edge, n8n, Dify), заметки (демо красит hex), подсказки порта (Dify, Langflow).
- Нет компенсации zoom для хрома и портов (n8n, Dify, tldraw). Порт 8px при fit-zoom 0.67 — 5.4px на экране; у
  ComfyUI точка тоже 8px, но зона 24px и рост ×1.25 на hover; RF UI 11px, Foblex 14px.

### 4.5 Пробелы в токенах

| Нет                                   | Следствие в демо                                    | У кого есть                         |
| ------------------------------------- | --------------------------------------------------- | ----------------------------------- |
| пары accent / on-accent               | `--demo-primary` + `color: white`                   | shadcn, tldraw `selected-contrast`  |
| `warning`                             | `--demo-warning` со своим dark-значением            | Foblex, tldraw, n8n, Dify           |
| ступеней border (subtle / strong)     | hover у select собран `color-mix` вручную           | Foblex, Dify                        |
| токенов движения                      | `120ms` в трёх местах, у частей — дефолт Tailwind   | Foblex (одна кривая 150ms), n8n     |
| третьей ступени тени (raised)         | нет hover / drag подъёма                            | Foblex `shadow-1..3`, tldraw `1..4` |
| `--vui-radius-surface` как переменной | `calc(var(--vui-radius) + var(--vui-space))` руками | shadcn (шкала от `--radius`)        |
| размера текста оболочки               | 13 / 14 / 16px в разных демо                        | ComfyUI `text-xs`, Dify `system-*`  |

Последняя строка — прямое следствие решения «текст — приложения». Возвращать типографические токены не обязательно:
достаточно одного размера по умолчанию на оболочке (`text-sm`) либо одной договорённости для всех демо.

### 4.6 Подача в документации

- Нет страницы-галереи состояний: шесть состояний порта описаны абзацем текста, ни одно не показано. RF UI — страница с
  превью на каждую часть.
- Overview — около трёх экранов прозы до первой картинки.
- Сцены мелкие (zoom 0.67–0.81), без фона и цвета; у Foblex и ng-diagram шаблоны сняты в читаемом масштабе.
- Два мёртвых правила и перекрытия хрома (раздел 2) — в витрине ДС.

## 5. Где @vflow/ui сильнее

- Дисциплина токенов выше, чем у React Flow UI: там семантические пары смешаны с `slate-300`, `gray-400`, `bg-white`,
  `emerald-600`.
- Обратная связь порта при соединении (valid / invalid, не только цветом) есть по умолчанию; xyflow и Vue Flow имеют
  классы, но ничего не рисуют.
- Отдельный фокус клавиатуры (у xyflow и Vue Flow focus = selected), forced-colors в каждой части.
- Концентрические радиусы и одна шкала отступов; у RF UI радиусы `rounded-md`, `rounded-sm` и `rounded-[9px]` рядом.
- Трёхуровневая модель того же класса, что у ng-diagram и Foblex, при 13 ролях против сотен переменных.

## 6. Предлагаемый порядок

1. Починить три дефекта из 2.1 и перекрытия из 2.2; в e2e проверять computed stroke, а не атрибут.
2. Тон: категориальная палитра (6 оттенков, пары light / dark) и `--vui-tone` на оболочке — плашка `vuiIcon`, порт,
   ребро, заметка.
3. Слой состояний оболочек: hover, мягкое кольцо выделения, подъём при drag, drop target, рамка статуса.
4. Рёбра: hover, тон, варианты, часть `vuiConnection` с цветом валидности.
5. Хром: фон во всех сценах, оформленный minimap, zoom-процент в controls, размещение панелей с отступом для fitView,
   placeholder и заметка.
6. Токены из 4.5.
7. Документация: галерея состояний, единый масштаб и шрифт сцен.

Пункты 2–3 дают большую часть визуального эффекта: после них четыре сцены перестают быть серыми без изменения модели.
