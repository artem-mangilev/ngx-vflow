# CSS-контракт и критерии production-готовности

Статус: приняты общие токены (Q16), модель состояний (Q15), пять отдельных страниц новой ng-doc секции (Q18) и два CSS-входа. Матрица приёмки согласована: фокус — функциональность и доступность, включая темы и варианты потребления. Производительность отложена. Обновлено: 2026-09-09. Этапы реализации находятся в [плане](plan.md); цвета и стилистика здесь не выбираются.

## CSS-токены

Приняты префиксы `--vflow-*` для core и `--vui-*` для UI. Это публичные тематические токены; уже существующие внутренние CSS-переменные позиционирования от этого не становятся публичными. При реализации каждый токен должен иметь конкретное использование и проверку override.

| Владелец / назначение                      | Стартовый набор                                                                                                              |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Core: общая палитра сцены и обратной связи | `--vflow-background`, `--vflow-surface`, `--vflow-foreground`, `--vflow-muted`, `--vflow-border`                             |
| Core: выделение и focus                    | `--vflow-selection`, `--vflow-focus`                                                                                         |
| UI: общий язык                             | `--vui-surface`, `--vui-surface-muted`, `--vui-foreground`, `--vui-muted`, `--vui-border`, `--vui-accent`, `--vui-on-accent` |
| UI: общая типографика                      | `--vui-font-family`, `--vui-font-size`, `--vui-line-height`                                                                  |
| UI: общий ритм и контур                    | `--vui-space`, `--vui-radius`                                                                                                |

Детализацию токенов пользователь пока остановил на этом наборе. Модель состояний принята по [исследованию аналогов](block-states-research.md); семантический тон индикатора и название прикладного статуса — разные понятия. BPMN использует общий язык темы, а детали фигур оформляются обычным CSS.

Принято Q12: публичными токенами задаются только общие значения. Для изменения padding карточки, высоты строки, размера порта или толщины линии используются обычные CSS-правила по семантическим частям. Публичные части должны иметь стабильные документированные селекторы; внутренний DOM core не становится контрактом. Маппинг UI → core задаётся в явной области темы; стили приложения могут переопределить оба уровня.

## Граница CSS и API поведения

- Цвет, шрифт, отступ, радиус, толщина видимой линии и видимый размер control — CSS.
- Координаты ноды, viewport zoom, направление/ID handle, тип маршрута ребра, resize constraints и допуски взаимодействий — данные или API поведения.
- Размер видимого порта не должен случайно уменьшать рабочую область попадания. Изменения геометрических CSS-токенов должны корректно обновлять измерения core.
- Состояния и семантические варианты могут передаваться через Angular API и выражаться в DOM; оформление этих состояний читает CSS-токены. Удаление `resizerColor` не означает удаление API состояния.

## Области темы

- На уровне редактора тема распространяется на HTML, SVG, markers, toolbar и minimap; light/dark могут одновременно существовать в разных редакторах.
- Принято Q13: пользователь может локально переопределить оформление ноды/ребра в рамках DOM-наследования. Toolbar и minimap используют тему редактора, без автоматической передачи локальных токенов ноды.
- Переключение поддерживаемой темы редактора обновляет minimap без изменения graph state и без пересоздания flow. Произвольное изменение любых внешних stylesheet нельзя считать автоматически наблюдаемым событием: механизм синхронизации canvas ещё выбирается.
- Для проверки достаточно двух простых тем без окончательной визуальной проработки. Переключение обновляет все заявленные слои без пересоздания графа и изменения его данных; пользовательские переопределения сохраняют приоритет.
- Поставляется precompiled CSS, без необходимости Tailwind у потребителя. Кастомизация доступна обычным CSS без обращения к внутреннему DOM core.

Приняты два CSS-входа из одного источника с одним Angular build: `@vflow/ui/styles.css` — готовый вариант по умолчанию, `@vflow/ui/styles.source.css` — исходник для pipeline потребителя. Основание — [исследование Tailwind](tailwind-delivery-research.md). Это позволяет выбрать pipeline потребления, но не даёт автоматического удаления неиспользуемых `.vui-*` правил. Оба файла публикуются в одном пакете и отмечаются в exports/sideEffects. Собственные стили отделяются от локальных директив генератора; source-вход не должен ссылаться на файлы монорепозитория. Tailwind у потребителя готового CSS не требуется.

## Принятое покрытие композициями

По запросу пользователя выполнено [исследование десяти потребителей React Flow](consumer-patterns-research.md). В Q18 приняты пять сцен на отдельных страницах новой ng-doc секции Design system: workflow с ветвлением, data/media pipeline, ERD/mapping, карта отношений/метрик и BPMN. Текущий обзор переносится из Introduction в эту секцию; сцены не объединяются на одной странице. Подробная матрица «страница → проверяемые паттерны» находится в этапе 5 [плана](plan.md).

Дополнительные проверки относительно MVP: богатое содержимое body; типизированные подписанные порты отдельно от строк ERD; заметка без портов; контейнер со своими connections; просмотр графа без обязательных affordances редактирования. Они проверяют композицию существующих частей и не означают новых image/chart/form/Markdown-компонентов.

Критерий широты — покрытие каждого паттерна работающей композицией. Наличие трёх или пяти страниц само по себе недостаточно. Текущий BPMN-код тоже должен быть доведён до уже выбранного subset, включая parallel gateway и разные sequence/message/association presentations.

## Согласованные критерии готовности

| Область                 | Проверка                                                                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Композиция              | Каждый принятый паттерн из исследования потребителей покрыт сценой; общие части переиспользуются, custom body/иконки/действия не требуют копировать реализацию оболочки                                                                                 |
| Геометрия               | Первый кадр, zoom, resize, длинные названия, rename/reorder полей и изменение типографики/плотности сохраняют корректные endpoints                                                                                                                      |
| Состояния и доступность | Проверены согласованные сочетания состояний, keyboard focus, accessible names, отсутствие конфликтов вложенных controls с жестами, forced colors и reduced motion там, где есть анимация                                                                |
| Темы                    | Два редактора с разными темами и standalone core на одной странице; тема распространяется на все заявленные слои; чистая смена цвета не вызывает пересчёт graph geometry                                                                                |
| Поставка                | Core-only consumer с собственными шаблонами не зависит от UI; UI работает из собранного пакета с compiled CSS без Tailwind и отдельно с source CSS через поддерживаемый pipeline; оба режима дают одинаковое оформление; экспорт BPMN работает отдельно |
| Миграция                | Старые presentation types и styling inputs удалены согласованно с примерами и migration guide; сохранены имена, endpoints, размеры и взаимодействия                                                                                                     |
| Браузеры — принято Q14  | Основные сценарии проверяются в Chromium; Firefox/WebKit не входят в обязательную приёмку первого этапа                                                                                                                                                 |

Scroll/collapse — отдельный эксперимент демо с фиксацией результатов. Этот этап не объявляет его стабильным библиотечным контрактом. Набор поддерживаемых Angular соответствует заявленному контракту выпуска и проверяется при сборке consumer; расширение этого контракта не следует из задачи дизайн-системы.

Замеры производительности, выбор нагрузочной сцены и численный бюджет регрессии отложены. Они не входят в обязательную приёмку этого этапа.
