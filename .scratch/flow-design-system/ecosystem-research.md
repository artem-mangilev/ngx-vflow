# Аналоги специализированной UI-системы для ngx-vflow

Дата проверки: **2026-09-06**. Источники: официальная документация и официальные примеры. Это исследование продуктовых границ и UI-паттернов, а не рейтинг популярности, проверка лицензий или тест производительности. Наличие функции в примере ниже не означает наличие готового компонента в основном npm-пакете.

Под «таблицами» здесь понимаются **сущности с полями и связи между конкретными строками**: ERD, schema mapping, data lineage. Универсальный data grid и просмотр наборов данных в задачу не входят.

## Главный результат

Прямой аналог идеи уже есть: **React Flow UI** отделяет готовые компоненты для флоу от основного графового API. В enterprise-сегменте **JointJS+** особенно полезен как каталог diagram-specific компонентов, а **GoJS Record Mapper** и **Foblex Schema Designer** — как проверка сценария «поле → поле». **bpmn-js** показывает, почему внешний вид BPMN нужно отделять от правил моделирования и формата документов. Это вывод по источникам ниже, а не утверждение, что их архитектуру нужно копировать целиком.

## Составные ноды и связи строк: самые полезные детали

**React Flow Base Node** уже раскладывает карточку на container, header/title/actions, content и footer. Документация отдельно требует отключать drag на вложенных интерактивных элементах через `nodrag`. Его **Database Schema Node** составлен из BaseNode, Table и LabeledHandle, экспортирует header/body/row/cell, а в примере создаёт handles у полей. Это хороший пример узкого предметного рецепта поверх небольшого набора UI-частей. [Base Node](https://reactflow.dev/ui/components/base-node), [Database Schema Node](https://reactflow.dev/ui/components/database-schema-node)

**GoJS Record Mapper** прямо связывает поля разных records: связь создаётся drag-жестом от строки, затем может быть переподключена; строки размещаются через Panel.Table. Отдельный связанный sample показывает selectable fields. Это ближе к data mapping, чем обычный ERD sample, где видимые строки могут быть просто атрибутами сущности. [Record Mapper](https://gojs.net/latest/samples/records)

**JointJS+ Record** — готовая составная shape, а не просто прямоугольник: API предусматривает item IDs, сворачивание, подсветку, определение видимости и bbox конкретного item. RecordScrollbar появляется, когда элементы не помещаются. Для динамического списка портов есть отдельная demo. Эти функции выявляют реальные вопросы длинных схем: что делать со связями к скрытым строкам, как подсвечивать конкретный mapping и как синхронизировать геометрию. Первые предложения здесь — факты API; последние вопросы — вывод для проектирования ngx-vflow. [Record API](https://docs.jointjs.com/api/shapes/standard/Record/), [Record scrollbar](https://docs.jointjs.com/learn/features/ready-to-use-shapes/records/), [Dynamic Port List demo](https://www.jointjs.com/demos/list)

**Foblex Schema Designer** объединяет table nodes, drag column-to-column, reconnect, inline name/type, key markers primary/unique/index, cardinality toolbar и context menus разных уровней — canvas/table/column/relation. Это наиболее близкий найденный Angular reference app для указанного сценария. Он собирается из flow primitives и application UI; не следует представлять весь этот набор как встроенный SchemaDesigner-компонент библиотеки. [Официальный пример](https://flow.foblex.com/examples/schema-designer)

Вывод для будущей проверки API: минимальная общая структура здесь — **entity container → field row → stable connection point**, плюс отдельно **relationship presentation**. Она может обслужить SQL ERD, source-target schema mapping и column lineage. Семантика PK/FK, преобразований или lineage остаётся у приложения. Нужны явные политики rename/reorder/delete/collapse, но из исследования не следует необходимость сразу реализовывать все режимы или универсальный schema engine.

## BPMN: три разных обещания

1. **Визуальный набор**: shapes/markers/labels, например event/task/gateway и типы линий. Это естественная область UI.
2. **Редактор нотации**: допустимые связи, boundary attachment, containment, pool/lane interactions, специализированные действия.
3. **Совместимость документов и семантики**: BPMN metamodel, import/export и roundtrip, сохранение свойств модели.

Это предлагаемая классификация, основанная на разделении `diagram-js` / `bpmn-js` / `bpmn-moddle`. Нельзя обещать второй и третий уровни лишь на основании появления первого. [Архитектура bpmn-js](https://bpmn.io/toolkit/bpmn-js/walkthrough/)

У **JointJS+** есть BPMN 2.0 shapes, настраиваемые через Inspector, а также composite pools, отдельные lanes/phases, горизонтальная/вертикальная ориентация и независимые стили частей. Это показывает, что pool — составной контейнер со своей геометрией и поведением, а не только рамка. Документация shapes сама по себе не доказывает соответствие полноценного моделера стандарту. [BPMN shapes](https://docs.jointjs.com/learn/features/ready-to-use-shapes/bpmn/)

## Какие правила стоит вынести в общее проектирование

Следующие пункты — **предложения для ngx-vflow**, выведенные из сравнения; это не заявленные vendor best practices.

1. **Разделить stable primitives, domain recipes и reference apps.** Node anatomy и field handle подходят для стабильного UI API; ERD/BPMN compositions могут быть рецептами; полный workflow editor — отдельное приложение-пример. React Flow Workflow Editor как раз добавляет поверх UI ELK layout, sidebar, dark mode и runner. Наличие runner в template не делает runtime задачей UI-kit. [Workflow template](https://reactflow.dev/ui/templates/workflow-editor)
2. **Тематизировать назначение, а не палитру продукта.** Surface, text, border, selected, focus, invalid, connection-preview полезнее привязки к конкретному blue-500. yFiles выделяет interaction states; Foblex публично отделяет semantic/alias tokens от primitives. [yFiles themes](https://docs.yworks.com/yfiles-html/dguide/customizing_view_theming/), [Foblex styling contract](https://flow.foblex.com/docs/default-theme-and-styling)
3. **Tailwind — вариант реализации/интеграции, не единственный контракт кастомизации.** При решении о libs/ui нужно независимо выбрать: исходники или compiled package; обязательный или optional Tailwind; CSS token overrides; замена содержимого Angular-компонентами. У сравниваемых библиотек есть все эти направления в разных сочетаниях.
4. **Не путать состояние редактора с состоянием процесса.** Selected/focused/connectable/dragging должны сосуществовать с running/failed/waiting. Иначе runtime error начинает спорить с рамкой выделения. Поддержка первого состояния относится к flow mechanics; представление второго может быть общим UI, но источник истины остаётся в приложении.
5. **Примитив строки должен сохранять адресность связи.** Имя поля и порядковый номер строки — UI-данные, не надёжная идентичность endpoint. Опорные примеры — field-to-field Record Mapper и item IDs/geometry Record. [GoJS mapper](https://gojs.net/latest/samples/records), [JointJS Record](https://docs.jointjs.com/api/shapes/standard/Record/)
6. **Не превращать libs/ui в общую Angular design system.** Для формы Inspector или меню полезны layout/slots и diagram context; собственные datepicker, общий data grid и schema-driven form engine не следуют из исследованных потребностей. Foblex custom-node example переиспользует Angular Material внутри нод. [Custom nodes](https://flow.foblex.com/examples/custom-nodes)

## Ограничения проверки

- Не проводились измерения bundle size, accessibility audit, production performance и совместимости конкретных версий Angular.
- Публичные каталоги и demos подтверждают наличие сценариев, но не размер спроса. Приоритизацию следует проверить реальными пользователями ngx-vflow и representative editor examples.
- Маркетинговые claims о лидерстве, полноте BPMN и производительности не переносились в рекомендации.
- В официальных документах встречаются смешанные версии и legacy pages. Существенные обнаруженные различия указаны явно: X6 3.x объединяет plugin packages; JointJS рекомендует composite pools вместо legacy pools; Foblex example использует прежние input/output connector names, тогда как актуальные getting-started docs предлагают unified connector API. Для реализации нужно выбирать docs под фактически установленную версию.
