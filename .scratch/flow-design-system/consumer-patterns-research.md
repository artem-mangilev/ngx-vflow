# Паттерны UI у потребителей React Flow

Дата: 2026-09-07. Вопрос: какими композициями проверять семантическую основу `@vflow/ui`, исходя из реальных продуктов, а не заранее выбранных отраслей.

## Метод и границы выводов

Отправные точки — [Case Studies](https://reactflow.dev/pro/case-studies) и [Showcase](https://reactflow.dev/showcase). Прочитаны все четыре case studies; из showcase выбраны продукты с различающимися задачами и доступным первичным описанием интерфейса. Ниже десять потребителей. Это курируемая подборка, не репрезентативная статистика рынка и не рейтинг популярности.

Факты в таблице подтверждены текстом официальных руководств, страниц продуктов или прямыми ответами их разработчиков в case studies. Изображения showcase не использованы как доказательство расположения частей или поведения: интерактивные интерфейсы и визуальные детали не проверялись в браузере. Выводы о наших примитивах и составе демо — проектные рекомендации, а не утверждения авторов источников.

Присутствие продукта в showcase подтверждает связь с React Flow на момент публикации; оно не доказывает, что каждая описанная сегодня функция реализована встроенным API React Flow. Branching, execution, формы, инспекторы, данные и предметные ограничения ниже — возможности приложений.

## Что это меняет для текущего MVP

В [public API](../../libs/ui/src/public-api.ts) и [директивах](../../libs/ui/src/lib/primitives.directive.ts) уже есть оболочка/header/body/footer, field, port, status, edge/label, group и BPMN outlines. Наблюдения поддерживают развитие этой основы, а не каталог готовых отраслевых нод.

Пробелы относительно согласованного плана — прежде всего в доказательстве композиции:

- Явно проверить произвольный body: изображение, несколько значений метрики, длинный текст, элемент управления приложения. Это требование к месту содержимого и обработке жестов, не запрос на image/chart/form-компоненты.
- Показать простую аннотацию без портов. Сначала композиция существующей оболочки и пользовательского HTML; отдельный primitive нужен только при обнаружении самостоятельного общего контракта.
- Проверить адресный порт у строки и типизированные подписанные порты у процессора. Один ERD-пример не доказывает оба режима.
- Проверить группу с заголовком и собственными connections; вложенность и переход в sub-map не объединять в одну обещанную функцию.
- Проверить режим просмотра на тех же частях: UI подключения/действий не обязателен. Это не новый «замок» viewport controls.
- Ввести документированные места заголовка/описания/метаданных/действий и сочетания состояний; исследование не требует директивы на каждый `<span>`.

## Минимальные проверочные композиции — предложение

Число демо является следствием покрытия. Для найденных различий предлагаются **четыре общие композиции плюс уже согласованный BPMN-набор**. Они могут быть пятью сценами на одной странице, без пяти полноценных приложений.

| Композиция                 | Что обязательно показать                                                                                                                                                     | Основание                                                                                                                                |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **Workflow с ветвлением**  | Trigger/step, описание, несколько именованных выходов, подпись/действие связи, диагностика вместе со статусом                                                                | OneSignal, Attio, CARTO                                                                                                                  |
| **Data/media pipeline**    | Несколько типизированных inputs/outputs, валидность подключения, свободный body с preview и элементом управления приложения, изменение размеров, локальный статус исполнения | chaiNNer + свободное содержимое DoubleLoop; preview внутри processor — наш проверочный пример, а не подтверждённый здесь layout chaiNNer |
| **ERD/schema mapping**     | Поля с именем/типом/индикатором, точная адресность, cardinality, rename/reorder; scroll/collapse только эксперимент демо                                                     | Hubql, ChartDB                                                                                                                           |
| **Карта отношений/метрик** | Численные метаданные, заметка/изображение, контейнер с заголовком и собственной связью, сценарий просмотра без affordances редактирования                                    | DoubleLoop, Bit, Ameliorate; вложенный граф дополнительно мотивирован Dify                                                               |
| **BPMN presentation**      | Ранее выбранные task/events/gateways/pool/lane/links и внешние подписи                                                                                                       | Уже принятое продуктовое решение; эта выборка не доказывает распространённость BPMN                                                      |

Можно объединить первые две сцены, если одна действительно показывает оба контракта: компактный шаг и насыщенный процессор с несколькими типизированными портами. Уменьшение числа страниц само по себе ничего не доказывает; удалять проверяемые различия ради числа «три» не следует.

## Границы production acceptance

Критерий широты: каждый паттерн выше сопоставлен с работающим примером и проверкой геометрии/состояний; «у нас пять демо» не критерий качества. Headless-consumer и UI-consumer остаются отдельными проверками поставки. Браузер — Chromium по принятому решению.

Палитра поиска нод, inspectors, execution engine, Markdown-редактор, таблица данных, charting, collaboration, undo/redo, auto-layout и предметные lifecycle не включаются в UI kit из-за наличия у конкурентов. В демо допустим пользовательский контент и простая имитация бизнес-состояния. Viewport controls остаются zoom in/out/fit view; набор общих CSS-токенов исследование не расширяет.

Для следующего обсуждения достаточно подтвердить матрицу покрытия и включение заметки/богатого body в reference compositions. Это ещё не решение добавить новые публичные компоненты.
