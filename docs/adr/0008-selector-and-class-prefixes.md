# One prefix per package

Every public selector of core starts with `v`, and every selector of `@vflow/ui` with `vui`: `[vHandle]`, `[vSelectable]`, `[vDragHandle]`, `g[vEdgeInteraction]`, `[vResizable]`, `[vNoDrag]`, `<v-minimap>`, `<v-node-toolbar>`, `ng-template[vNode|vEdge|vConnection|vMarker]` and `*vEdgeLabel` in core; `[vuiNode]`, `[vuiPort]`, `<vui-controls>` in UI. The `vflow` element keeps its name. Short unprefixed names such as `selectable` or `resizable` could collide with other libraries in the same template, and a single prefix per package tells the reader which package an attribute belongs to.

Public core classes are `Vflow*Directive` / `Vflow*Component`, including the template directives and the `ngx-vflow/testing` mocks; UI classes and types are `Vui*` without a suffix. The minimap is spelled as one word everywhere (`VflowMinimapComponent`, `MinimapPosition`). A directive input that shares its selector's name is renamed with it (`vResizable`, `vEdgeLabelOrient`, `vMarker`). Old selectors get no aliases: the change ships in the 3.0 major with a migration table.

The same prefixes apply to the DOM and CSS contract: core CSS classes `.v-*` (internal ones included, with BEM modifiers such as `.v-resize-control--handle`), tokens `--v-*` and data attributes `data-v-*` (`data-v-handle-state`, `data-v-no-drag`); UI classes `.vui-*`, tokens `--vui-*` and data attributes `data-vui-*` (`data-vui-tone`, `data-vui-state`).

Amended 2026-10-31: a class is a hook for styles and a data attribute is a hook for behaviour. The roles that the library's own code reads from the DOM are data attributes (`data-v-handle-type`, `data-v-drag-handle`, `data-v-reconnect-handle`, `data-v-resize-control`, `data-v-no-drag`, `data-v-no-pan`, `data-v-no-select`, `data-v-no-keyboard`), and the elements the library needs (the root, the pane, the viewport) are registered in a service, so the library never selects by class, with one exception: the entity hosts `.v-node` and `.v-edge`, whose classes are the public identity of an entity in the DOM. Only the classes the documentation names are part of the contract; the other `.v-*` classes (layers, wrappers, magnets, the focus indicator) keep the prefix so that they cannot collide, but applications must not rely on them.

This supersedes the part of ADR-0001 that retained the `[resizable]` name and the `data-vflow-handle-*` attribute names of ADR-0007.

Considered and rejected: `vflow*` selectors for core, because they are long in every template and `@vflow/ui` already used `vflowNode`, `vflowEdge` and `vflowEdgeLabel`; keeping the template slots unprefixed because they only match on `ng-template`, since the prefix rule is easier to follow without exceptions; suffix-less core classes, because `Vflow` is already the imports array and `VflowComponent` would become an exception.

Amended 2026-11-01: the entity hosts are identified by data attributes, not classes: `data-v-node="<id>"`, `data-v-edge="<id>"` and `data-v-handle`. A class was a style hook with a second meaning, and an identity is read by code (the library's own click check, tests, applications), so it follows the rule above. Core also writes its interaction state to the hosts as attributes, `data-v-selected` and `data-v-preselected`, next to `data-v-handle-state` on handles, so `@vflow/ui` and applications read every core state from the DOM the same way and bind nothing. Public classes remain only for the parts core draws (`.v-root`, `.v-selection-box`, `.v-resize-control`, `.v-alignment-guides`, `.v-background-pattern`), as style hooks named like their tokens; `@vflow/ui` data attributes are `data-vui-connected` and `data-vui-reveal` on the port, no longer `data-vui-state` or `data-vui-selected`.

Amended 2026-11-01, second part: the parts core draws are selected by data attributes too, so no public `.v-*` class remains: `data-v-root`, `data-v-background-pattern`, `data-v-selection-box`, `data-v-alignment-guides` with `data-v-alignment-guide="line|point"`, `data-v-resize-control="handle|line"` with `data-v-resize-control-position="top|…|bottom-right"`, `data-v-reconnect-handle`, `data-v-interactive-edge`, `data-v-marker="<type>"`. A core token is named after its attribute (`--v-selection-box` for `[data-v-selection-box]`). BEM modifiers become attribute values, which CSS matches exactly or by prefix (`[data-v-resize-control-position^='top']`). The remaining `.v-*` classes are internal (layers, wrappers, magnets, the focus indicator, the minimap host) and applications must not rely on them.
