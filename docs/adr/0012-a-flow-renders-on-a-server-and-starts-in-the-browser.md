# A flow renders on a server and starts in the browser

A `vflow` renders in a server render and in the prerender of a build without an error: an application with Angular SSR, which `ng new` offers by default, can have a flow on a server-rendered route. The server renders the flow element, the node and edge presentations of the application and the parts placed in it; it measures nothing, emits no `initialized`, and `fitView()` resolves to `false`, as in a DOM without layout (ADR-0009).

A server render is not treated as a DOM without layout, though. jsdom never lays out, so there the flow hides nothing; the HTML of a server is laid out later, by the browser that receives it. The flow therefore waits for the first layout on a server as it does in a browser: its host has `v-initializing` and not `v-no-layout`, entities carry `data-v-pending`, and only the canvas is painted. A reader of a prerendered page sees the canvas, not unmeasured nodes under an unfitted viewport, until the application starts.

The `vflow` host carries `ngSkipHydration`: Angular creates the flow anew in the browser instead of adopting the DOM of the server. The flow moves its own elements between layers (resize controls, node toolbars, edge labels), so the DOM a server sends is not the one hydration expects, and hydrating a server-rendered flow failed with NG0501. Nothing is lost: nothing of the flow is painted before its first layout.

Core takes the document from the injector and its window from that document, and never reads the globals `window` and `document` while it is created or destroyed; a gesture reads the window when it starts, which no server render reaches. What cannot be measured without layout is skipped, not faked: an image background is not loaded, and the bounds of a custom curve path are `null` (in jsdom too, where the measurement used to throw). A server knows no reader, so the platform is not a Mac there and shortcut labels are the non-Mac ones until the browser renders them again.

The specs in `libs/ngx-vflow/server` render an application with `@angular/platform-server` in Node, where no global DOM exists, and fail on any console error or warning, including those of the teardown.

Considered and rejected: rendering nothing inside `vflow` on a server, because the parts an application places in the flow are created by the application's own template anyway, and a template that branches on the platform is what Angular advises against; hydrating the flow, because it would forbid the flow to move its elements; drawing nodes and edges on the server from the positions of the nodes, because handle positions and content sizes are unknown without layout, so the edges would be wrong; leaving it to applications to wrap every flow in `@defer`, because every application with SSR would have to know that.
