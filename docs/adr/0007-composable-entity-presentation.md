# Compose entity presentation from data components and declarative parts

A node or edge is drawn either by the component named in its `component` field or by the single `ng-template[node]` / `ng-template[edge]` fallback, and everything that lives inside an entity (handles, edge labels, resize controls) is declared in that presentation. The library owns geometry, layers and interaction; the application owns DOM and appearance. This replaces a node union discriminated by `type`, a separate group template, a required component base class, template-only edges, the `<handle>` component and label data with a global label template.

- **One node model.** `Node` is one interface without `type`. `html-template`, `template-group`, `groupNode` and their types and guards are removed; a group is a node with `width` and `height` and children that reference it through `parentId`, and group behavior (accessible name, group layer, minimap, drag filtering) follows from having children. Application node kinds live in `data`, which the library does not read.
- **Component decides rendering.** A node or edge with `component` (a class or a lazy import function) renders that component; otherwise the template renders. `nodeHtml` becomes `node`, matching `edge`.
- **Components without inheritance.** Components are created with `createComponent` and read their entity through DI (`injectNode()` / `injectEdge()`), which returns the same object a template gets as `let-ctx`. `CustomNodeComponent` is removed. The event bus stays: outputs are discovered with `reflectComponentType`, so `@Output()`, `output()` and `outputFromObservable()` all reach `componentNodeEvent` / `componentEdgeEvent`.
- **Component edges on an SVG host.** An edge component is created with an `<svg:g>` inside the edge SVG as its host element, so it draws arbitrary SVG. The interaction stroke is part of the presentation through `edgeInteraction`, and without it the edge has no hit area.
- **Handle is a core directive.** `[vflowHandle]` on any element registers, measures and positions it (`layout: 'auto' | 'manual'`) and exposes state as `data-vflow-handle-*` attributes and directive signals; size and look belong to the application or to `vflowPort` from `@vflow/ui`, which is itself a handle.
- **Labels are declared inside the edge.** An `edgeLabel` template next to the edge's SVG elements renders in the HTML label layer at `start`, `center` or `end`; `Edge.edgeLabels` and `edgeLabelHtml` are removed and label text comes from edge data.

Considered and rejected: removing the event bus in favor of application services, since the owner chose to keep it; an HTML edge host containing a library-drawn `<svg>` (the ng-diagram and Foblex model), because it would rework reconnection and selection and narrow what an edge can draw; a transitional deprecated `<handle>` wrapper, `provideHandleDefaults()` and a separate `injectHandle()` / `HANDLE_REF`, because each added a second way to express the same handle role or state; `vflowHandle="source"` as the type input, because a component applying the directive through `hostDirectives` could not forward it under the selector name without applying the directive twice; unprefixed `data-type` / `data-state` attributes, because they collide with application and `vflowPort` attributes; `labelPoints` in the edge context for SVG text labels, because it would be a second label rendering path to maintain; and a numeric `0..1` label position along the path, deferred because custom curves would need path sampling.

The cost is a breaking change to node data, templates, component nodes, handles, labels and the testing mocks, described in the version 3 migration guide.
