# Types flow through the boundaries

The data type of a node or edge, `Node<T>` and `Edge<T>`, reaches every place a consumer meets it. `VflowComponent<N extends Node, E extends Edge>` is generic in the node and edge types of its `nodes` and `edges` inputs; strict templates infer them from the bindings, so `$event` of the drag, connection and reconnection outputs carries the application's types, and the query methods (`getNode`, `getNodesAtPoint`, `getIntersectingNodes`, `getDetachedEdges`) return them. The outputs live on the component itself, not on host directives, because a host directive cannot see the component's type parameters; `ViewportCullingDirective` stays a host directive because it has no outputs. The only casts are at that boundary, in the component, on the invariant that the models hold the objects of the inputs.

A `vNode` or `vEdge` template takes an optional type witness, `of` (`vNodeOf` / `vEdgeOf`), the `NgFor` pattern: a generic structural directive whose context guard types `let ctx` from an input that is never read at runtime. Without the input the type parameter defaults to `any`, so a template that does not name its nodes keeps reading `ctx.data()` untyped, as before.

`(componentNodeEvent)` and `(componentEdgeEvent)` are `AnyComponentNodeEvent` / `AnyComponentEdgeEvent`, never `any`. An event carries the component class that emitted it, which `isComponentNodeEvent(event, Cmp)` and `isComponentEdgeEvent(event, Cmp)` compare at runtime to narrow the event to `ComponentNodeEvent<[Cmp]>`, the union of the outputs of that class. A handler can no longer declare `ComponentNodeEvent<[A, B]>` as its parameter type: that pattern was only sound because the output was `any`.

Three smaller rules follow from the same principle. A collection the library only reads is `readonly` (`nodes`, `edges`, `getNodesBounds(ids)`, `FitViewOptions.nodes`, `panOnDrag`, `allNodes`/`allEdges` of a curve factory). A state with one meaning has one encoding: a missing handle id is `undefined`, never `''`, and the release of a connection gesture is one `ConnectionEventOutcome`, `{ valid: null; to: null } | { valid: boolean; to: { node; handle } }`, instead of three nullables. Type-only names are re-exported with `export type`, so the entry point also compiles under `isolatedModules`.

Kept as they are: `NodeRef.data` and `EdgeRef.data` read as an empty object for an entity without a `data` signal, which keeps `ctx.data().title` from throwing in a template, and `createNodes()` drops data-less nodes from the inferred union; both are documented on the types rather than changed.

Considered and rejected: return-only type parameters on the query methods (`getNode<T>()`), because they are assertions dressed as inference; a type parameter on `NodeRef`'s template context without a witness, because a template cannot pass one; `componentNodeEvent` typed `OutputRef<any>` so that a narrowed handler parameter compiles, because the `any` leaked into `subscribe()` and `outputToObservable()`; a `component` input on the flow listing the component classes, because the guard needs no declaration and checks the class at runtime.
