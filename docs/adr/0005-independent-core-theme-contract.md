# Keep the core theme contract independent of UI

ngx-vflow owns overrideable CSS tokens with defaults for its standalone presentation needs. An optional @vflow/ui theme sets values for those core tokens, while core remains independent of the UI package. This preserves a usable core-only integration and lets applications theme engine feedback without adopting the first-party UI theme; moving default presentations into UI does not remove core's own theme contract.

UI depends on core, so UI parts read the core tokens directly for every value core already has (background, surface, foreground, muted, border, selection, focus), and UI declares its own `--vui-*` tokens only for values core lacks (accent, fills, tones, shadows, scales). A concept has one public name: an override of `--v-surface` on any element recolors the flow and the parts under it alike. Amended 2026-10-19: UI used to keep a parallel `--vui-*` set mapped onto core in the theme scope, which gave consumers two names for one color and broke overrides below the scope, because the mapping resolves on the scope element. The cost is that UI parts outside a `data-vui-theme` scope render with core's defaults.

CSS is the public styling contract: shared theme values use general semantic tokens, while part-specific details use ordinary CSS instead of a component-token catalogue. Programmatic presentation parameters such as `resizerColor` are removed during the major migration. User token overrides take precedence over UI theme values, which take precedence over core defaults; importing UI CSS alone must not theme a standalone flow outside an explicitly themed scope.

Local CSS variables follow ordinary DOM inheritance. The minimap uses the editor theme; local node themes are not copied into separate rendering layers automatically. A node toolbar sits inside the node DOM, so it inherits the node's local theme.
