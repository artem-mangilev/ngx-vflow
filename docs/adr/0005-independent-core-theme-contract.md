# Keep the core theme contract independent of UI

ngx-vflow owns overrideable CSS tokens with defaults for its standalone presentation needs. An optional @vflow/ui theme sets values for those core tokens, while core remains independent of the UI package. This preserves a usable core-only integration and lets applications theme engine feedback without adopting the first-party UI theme; moving default presentations into UI does not remove core's own theme contract.

Tokens have three levels, each with one owner (amended 2026-10-20). Core has one token per part it draws itself, named after its public class (`--v-selection-box`, `--v-resize-control`, `--v-alignment-guides`, `--v-background-pattern`, `--v-minimap-mask`, `--v-focus` and its geometry), and reads nothing else; it has no palette. The UI theme owns the design-system roles (`--vui-background`, `--vui-surface`, `--vui-foreground`, `--vui-muted`, `--vui-border`, `--vui-accent`, tones, shadows, scales); the parts read only those. A mapping block in the theme file sets the core tokens from the roles. As with shadcn, a theme is a scope (`:root` or an element with `data-vui-theme`) and the mapping is declared on every scope, because a custom property that references another one resolves on the element that declares it: roles are overridden on a scope for core parts to follow, and a core token on any element inside the scope changes that one part. This replaces the 2026-10-19 amendment, under which the parts read core tokens directly so that a concept had one public name: core then carried a theme palette (`--v-surface`, `--v-muted`, an accent named after selection) that its few feedback parts borrowed by approximation, and one of those parts could not be recolored alone.

CSS is the public styling contract. A core token exists only for a part core draws: its colors, plus the focus ring geometry and the node toolbar offset; other details of a part (sizes, widths, shapes) are ordinary CSS on its class. Programmatic presentation parameters such as `resizerColor` are removed during the major migration. User token overrides take precedence over UI theme values, which take precedence over core defaults. Importing core alone never themes a flow. The UI tokens reach an application only when it copies them in with the UI generator, so copying them is the opt-in: their light theme sits on `:root`, like shadcn's, and every flow of that application takes it without an attribute; `data-vui-theme` switches a subtree to dark or back to light (amended 2026-10-19, replacing "importing UI CSS alone must not theme a flow outside an explicit scope").

Local CSS variables follow ordinary DOM inheritance. The minimap uses the editor theme; local node themes are not copied into separate rendering layers automatically. A node toolbar sits inside the node DOM, so it inherits the node's local theme.
