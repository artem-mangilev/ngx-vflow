# Configure flows through provideVflow features

Application-wide configuration of flows goes through `provideVflow(...features): Provider[]`, placed in the providers of `bootstrapApplication`, of a route or of the component that hosts a flow. A feature is a `VflowFeature`: a kind and the providers that install it, built by a `with*()` function of the library or, for a package or an application, by `vflowFeature(kind, providers)`. The function returns plain providers, not `EnvironmentProviders`, because the component level is the main place to override, and it provides values only: every service of a flow stays on its element.

Each feature provides its own token, and its provider lays the given value over the value of the same token from the injector levels above (`skipSelf`), so a feature closer to a flow adds keys to one further up instead of replacing it. A setting is resolved per flow as the bound input, else the nearest provided value, else the library default, with object settings merged key-wise through the three layers. For that the settings inputs of `vflow` carry no default of their own: an unbound input reads `undefined` and does not take part, and `VflowComponent.settings` exposes the settings in effect, one signal each, for packages such as `vuiControls` and applications that read a flow's configuration.

Four features ship in the core. `withSettings()` takes the inputs of `vflow` by their names, `VflowSettings`, as an object, a signal or a factory run in the injector. A catalog with a merge rule of its own gets a feature of its own and loses its input, so that one value has one source: `withAccessibility()` takes the `AriaLabelConfig`, since labels are localization and typically come from a service for the whole application, and `withShortcuts()` takes the `KeyboardShortcuts`, merged section by section, since the keys of the graph are set once for an application or a user. `withNodeComponents()` and `withEdgeComponents()` register components under keys, so `Node.component` and `Edge.component` accept a string; a model resolves the key once, when it is created, and a key no level registers throws, as the missing component of a route does. The empty `VflowNodeComponents` and `VflowEdgeComponents` interfaces let an application augment the keys so that a typo is a compile error; without augmentation any string is accepted.

Considered and rejected: `makeEnvironmentProviders`, because it forbids the component level; a configuration object as the first argument, `provideVflow({ minZoom }, ...)`, because the overload and the sniffing of a `kind` give the function two shapes for one job; grouped features such as `withViewport()` and `withSelection()`, because they multiply names and leave keys like `background` without an obvious group, and they can be added later as sugar over the same token; "the nearest `provideVflow` wins as a whole", because two levels could not cooperate; a silent fallback to the `vNode` template for an unknown component key, because it hides a programming error; and keeping the `ariaLabelConfig` and `keyboardShortcuts` inputs next to their providers, because each would be a second source of truth for one value.
